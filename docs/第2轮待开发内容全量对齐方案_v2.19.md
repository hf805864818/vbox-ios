# vbox 第 2 轮 · 待开发内容全量对齐方案 v2.19（网盘全链路三轮深挖终版）

> **版本**：v2.19 —— 在 [v2.18](computer:///workspace/docs/第2轮待开发内容全量对齐方案_v2.18.md) 基础上，对**设置 → 网盘授权中心 → 获取 token → 详情页 → 资源播放**这条完整链路做 **3 轮真正深挖**（覆盖度 / 数据流一致性 / 播放链路消费）。

## 第 1 轮 · 链路覆盖度深挖（逐文件通读）

### 🔴 断点 1：**真实登录网关未接入**——`UnavailableCloudDriveLoginGateway` 直接抛错

**证据**：
- [login_gateway.dart:82-130](file:///workspace/lib/presentation/pages/cloud/login_gateway.dart#L82)：`startQrLogin`/`sendSmsCode`/`submitAccountLogin` 全部 `throw CloudDriveLoginException(...)`
- [node_login_gateway.dart:34-35](file:///workspace/lib/presentation/pages/cloud/node_login_gateway.dart#L34)：`supports` 仅覆盖 **B 站扫码**（`type == bilibili && mode.isQr`），其余 13 个网盘类型全走 `UnavailableCloudDriveLoginGateway`

**影响**：用户点「网盘账号授权」→ 除 B 站外，**13 个网盘全部报错「Node 常驻系统未就绪 / 原生登录链路尚未接入」**。

**iOS 端对照**：`NodeCloudDriveLoginGateway` 覆盖全部网盘（B 站扫码 + 夸克/UC/阿里 PG 扫码 + 短信 + 账号密码）。

---

### 🔴 断点 2：**Token 传递链路断裂**——登录写入的凭据无法到达播放链路

**证据**：
- 登录写入：`CloudDriveCredentialStore`（`cloud_drive_credentials_v1`）→ `PrefsManager` → 安全存储
- 播放读取：[pan_player.dart](file:///workspace/lib/platform/player/pan_player.dart) **全文件 0 引用** `credential`/`token`/`cookie`/`BDUSS`/`STOKEN`/`refreshToken`/`accessToken`
- 详情页：[detail_page.dart](file:///workspace/lib/presentation/widgets/detail_page.dart) **全文件 0 引用** `PanPlayer`/`网盘`/`CloudDrive`

**含义**：即使登录成功，Token 也**无法到达播放链路**——`PanPlayer` 根本不知道有凭据可用。

**iOS 端对照**：`CloudDriveManager` 统一持有凭据，`playXxxEpisode` 从 `CloudDriveManager.shared` 读取。

### 🔴 断点 3：**授权中心 `testCredential` 是假实现**

**证据**：
- [cloud_drive_auth_controller.dart:264-268](file:///workspace/lib/presentation/pages/cloud/cloud_drive_auth_controller.dart#L264)：`testCredential` 只更新 `lastCheckedAt`，**不做真实网络校验**
- 注释明确写：「真实网络校验随 F-02 授权链落地」

**影响**：用户点「测试」按钮 → 永远显示「已授权」，即使 Token 已过期。

---

### 🔴 断点 4：**详情页无网盘分支**

**证据**：
- [detail_page.dart:169-209](file:///workspace/lib/presentation/widgets/detail_page.dart#L169)：播放流程是直线 `resolvePlayUrl` → `PlayerController.open`，**不识别 `sourceType`、不调用 `PanPlayer`**
- [playback_route.dart:10-25](file:///workspace/lib/platform/player/playback_route.dart#L10)：`PlaybackRoute` 枚举有 `pan`，但 `PlaybackRouteResolver.resolve` **无网盘分支**——网盘直链被路由到 `detail`（影视）而非 `pan`

**影响**：即使 Token 存在，详情页也**不知道这是网盘源**，不会走网盘播放链路。

### 🔴 断点 5：**PanPlayer 原生盘直接报错**

**证据**：
- [pan_player.dart:184-186](file:///workspace/lib/platform/player/pan_player.dart#L184)：`PanPlayChannel.native` → `throw PanPlayException('原生路链尚未接入')`

**影响**：即使前面链路全通，原生盘也**无法播放**。

## 第 2 轮 · 数据流一致性深挖（交叉验证）

### 🔴 发现 A：**登录写入的凭据结构 vs 播放读取的结构不一致**

**登录写入**（`CloudDriveCredentialStore`）：
```json
{
  "quark": {
    "driveType": "quark",
    "authType": "qr",
    "cookie": "...",
    "accessToken": "...",
    "refreshToken": "...",
    "state": "valid"
  }
}
```

**播放读取**（`PanPlayer`）：
- **全文件 0 引用** `credential`/`token`/`cookie`/`accessToken`/`refreshToken`
- 只有 `cache`（`CloudPlayItemCacheStore`）——缓存的是**播放地址**，不是**登录凭据**

**结论**：登录写入的凭据**无法被播放链路消费**。

---

### 🔴 发现 B：**百度网盘特殊字段（BDUSS/STOKEN）无传递通道**

**证据**：
- `CloudDriveCredential` 有 `cookie`/`accessToken`/`refreshToken` 字段，但**无 `bduss`/`stoken` 专属字段**
- iOS `CloudDriveManager` 有 `BDUSS`/`STOKEN` 专属处理（`normalizeBaiduCookie`）
- `NodeCredentialSyncService` 有 `refreshCookie`/`refreshToken` 字段映射（`node_credential_sync.dart:123-125/203-205`），但**仅覆盖 Node 托管盘**

**结论**：百度网盘的 BDUSS/STOKEN **无法通过现有凭据结构传递**。

---

### 🔴 发现 C：**凭据状态（valid/expired/invalid）无消费**

**证据**：
- `CloudDriveCredential` 有 `state` 字段（`valid`/`expired`/`invalid`）
- `CloudDriveAuthController.testCredential` 只更新 `lastCheckedAt`，**不改 `state`**
- `PanPlayer` 全文件 0 引用 `state`/`expired`/`invalid`

**结论**：即使凭据过期，播放链路也**不知道**。

## 第 3 轮 · 播放链路消费深挖（反向追踪）

### 🔴 发现 D：**Node playID 稳定匹配缺失**

**证据**：
- iOS [PlayerViewsV2.swift:3768-3777](file:///workspace/vbox/Views/PlayerViewsV2.swift#L3768)：`nodeStableFileKey` 从 playID（base64 JSON）解析 `fileId`，用于跨次解析匹配同一文件
- Node 每次 detail 重新生成 playToken，同一文件的 playID 整串不同
- iOS 匹配顺序：playID 整串 → fileId → 文件名
- Flutter `PanPlayer.prepare` 用 `entry.playID` 作为缓存键——**playID 变化即缓存失效**

**影响**：同一网盘资源多次播放 → 每次重新解析 → 缓存形同虚设。

**iOS 端对照**：`nodeStableFileKey` + `nodePlayIDFileName` 双重兜底匹配。

---

### 🔴 发现 E：**vboxParams fragment 解析缺失**

**证据**：
- iOS [PlayerViewsV2.swift:2982-3010](file:///workspace/vbox/Views/PlayerViewsV2.swift#L2982)：`splitVboxFragment`/`appendVboxFragment` 解析分享链接中的 `vbox_fid`/`vbox_fsid`/`vbox_node`/`vbox_route` 参数
- 用途：详情页指定剧集（用户点击第 3 集 → vbox_fid=xxx → 播放器直接定位到第 3 集）
- Flutter `detail_page.dart` **无 fragment 解析**——`resolvePlayUrl` 直接传完整 URL

**影响**：详情页点击「第 3 集」→ 播放器从第 1 集开始播放 → 用户需手动选集。

**iOS 端对照**：所有网盘（阿里/百度/夸克/UC/迅雷/115/123/Node）都支持 `vboxParams` 定位。

---

### 🔴 发现 F：**网盘播放内核策略缺失**

**证据**：
- iOS [PlayerViewsV2.swift:3800-4100](file:///workspace/vbox/Views/PlayerViewsV2.swift#L3800)：`playDriveVideo` 有复杂的内核选择矩阵：
  - 百度本地代理 → MPV/MDK（禁止 AVPlayer）
  - 夸克 m3u8 → MDK 优先
  - 夸克直链 → IJKPlayer 优先
  - UC 直链/代理 → MDK/IJK/VLC（禁止 AVPlayer + 禁止 MPV）
  - Node 代理流 → 按文件名判定（MKV/HEVC → 兼容内核）
  - 阿里转码 m3u8 → AVPlayer（不走代理）
  - 阿里原画 → 本地代理
- Flutter 统一用 `media_kit`，**无按网盘类型的内核选择策略**

**影响**：不同网盘的特殊格式（百度大文件 HEVC、夸克 4K HDR、UC CDN Range 请求）可能播放失败。

**备注**：Flutter 统一用 media_kit 是架构决策，但**需要按网盘类型注入不同的配置参数**（如特殊 UA、代理设置、缓冲策略）。

## 本轮新增（115 → 118 项）

### 🔴 F-P26 · Node playID 稳定匹配 — P2

**问题**：见发现 D。Node 每次 detail 重新生成 playToken，Flutter `PanPlayer` 用 playID 作为缓存键导致缓存失效。

**开发步骤**：
1. 新增 `NodePlayIDMatcher`（对齐 iOS `nodeStableFileKey`/`nodePlayIDFileName`）：
   - `stableKey(playID)`：base64 decode → 取 `fileId`（优先）或 `playToken.fid`
   - `fileName(playID)`：base64 decode → 取 `name`
2. `PanPlayer.prepare` 缓存键改为 `provider|stableKey`（而非 `provider|playID`）：
   - 先按 `stableKey` 查缓存；
   - 未命中再按 `fileName` 查缓存；
   - 仍未命中才走解析；
3. 缓存写入时用 `stableKey` 作为键；
4. 详情页传递 `vbox_node` 时，用 `stableKey` 匹配而非 playID 整串。

**验收**：同一资源多次播放命中缓存；playID 变化不影响缓存命中。

---

### 🔴 F-P27 · vboxParams fragment 解析 — P2

**问题**：见发现 E。Flutter 详情页不解析分享链接中的 `vbox_fid`/`vbox_fsid`/`vbox_node`/`vbox_route` 参数。

**开发步骤**：
1. 新增 `VboxFragmentParser`（对齐 iOS `splitVboxFragment`/`appendVboxFragment`）：
   - `split(url)` → `(baseURL, params)`；
   - `append(url, params)` → 带 fragment 的 URL；
2. 详情页 `resolvePlayUrl` 接入：
   - 解析 `vod_play_url` → 提取 `vbox_fid`/`vbox_fsid`/`vbox_node`/`vbox_route`；
   - 传递给 `PanPlayer` / `PlayerController`；
3. `PanPlayer.prepare` 接入：
   - `vbox_fid` → 文件列表中定位对应文件；
   - `vbox_route` → 夸克线路偏好；
4. 播放器选集面板接入：
   - 显示文件列表时，高亮 `vbox_fid` 对应的文件；
   - 切集时更新 URL fragment。

**验收**：详情页点击第 N 集 → 播放器直接定位到第 N 集；分享链接带参数可正确解析。

---

### 🔴 F-P28 · 网盘播放内核策略 — P2

**问题**：见发现 F。iOS 按网盘类型选择不同播放内核/配置，Flutter 统一用 media_kit 无差异化策略。

**开发步骤**：
1. 新建 `PanPlaybackStrategy`（对齐 iOS `playDriveVideo` 内核选择逻辑）：
   - `strategyFor(url, driveType, fileName)` → 返回播放配置；
2. 各网盘策略：
   - 百度：`User-Agent` 伪装（`baiduPCSUserAgent`）+ `Referer` + 本地代理优先；
   - 夸克：m3u8 转码流特殊处理（TS 切片兼容性）+ 直链重连策略；
   - UC：Android UA（避免 CDN 拒绝 Range）+ 禁用部分解码器；
   - 阿里：转码 m3u8 直接播放（不走代理）+ 原画走代理；
   - Node：按文件名判定封装格式（MKV/HEVC → 软解优先）；
3. `PlayerController.open` 接入策略：
   - 打开前调用 `PanPlaybackStrategy.strategyFor`；
   - 根据策略调整 `PlayerSource.headers` / `PlayerConfiguration`；
4. 播放器内核兼容性矩阵（与 R-01 联动）：
   - 百度/UC/夸克大文件 → 禁用某些硬解；
   - HEVC/10bit/HDR → 启用软解回退。

**验收**：各网盘视频可正常播放；特殊格式（HEVC/4K HDR）不黑屏；Range 请求正常。
