# 网盘账号授权对齐修复方案 v1.0

> 范围：Flutter 端「网盘管理 ~ 网盘账号授权」对齐 iOS 原生端（`vbox/`）。
> 基线：iOS `CloudDriveAuthManager.swift` / `CloudDriveManager.swift` / `SettingsViews.swift` / `BaiduWebViewBridge.swift`。
> 关联问题：百度播放报「百度登录态正常，但未取得用户态 bdstoken，无法创建 vbox 转存目录」。

---

## 0. 问题总清单与优先级

| 编号 | 问题 | 影响 | 优先级 |
|---|---|---|---|
| P0-C | 百度播放链 bdstoken 兜底层缺失（登录不存、播放无保存值回退、WebView 层无 JS 提取） | **直接阻断百度播放**（用户实测报错） | P0 |
| P0-B | 阿里 refresh_token 刷新结果不落库 | refresh_token 轮换语义下**凭据自毁** | P0 |
| P0-A | 阿里登录主路径缺 OpenList（只有已废弃的 PG 扫码） | 阿里登录方式与 iOS 主路径不一致 | P0 |
| P1-A | 百度/夸克/UC 的 Node 扫码入口断裂（按钮矩阵/卡序缺 Node 项，Node 网关成死代码） | Node 扫码不可达 | P1 |

| P2-6 | 阿里刷新链少 OpenList renewapi 层 | 与 iOS 四层刷新链少一层 | P2 |

## 1. P0-C 百度 bdstoken 三层修复（最先做，直接恢复播放）

### 对齐依据（iOS 四层）

`baiduFetchUserBdstokenLocal`（CloudDriveManager.swift:4684-4731）：
1. `GET pan.baidu.com/api/gettemplatevariable`（登录态 Cookie + 桌面 UA + `Referer: https://pan.baidu.com/disk/main`）
2. 回退抓 `pan.baidu.com/disk/main` 静态 HTML 正则
3. 回退真实 WKWebView 载入 disk/main + **JS 注入提取**（`BaiduWebViewBridge.loadPanPageForBdstoken`，BaiduWebViewBridge.swift:133-152：`window.locals.get('bdstoken')` / `window.context.bdstoken` / 正则三重）
4. 回退**授权中心保存值** `credential.extra["bdstoken"]`（CloudDriveManager.swift:4726-4728）

保存值来源：登录时 `baiduEnrichAccountCookie`（CloudDriveAuthManager.swift:1262-1316）串行访问 5 个端点补齐 BFESS 系 Cookie 并取回 bdstoken/uk/username；`saveBdstokenCredential`（CloudDriveManager.swift:4761-4762）把 `bdstoken`/`bdstoken_source` 写进 `credential.extra`。

### Flutter 现状

- 登录侧只存 BDUSS/STOKEN，`extra` 仅 `cookie_mode`（native_cloud_drive_login_gateway.dart:415-421）——**无 enrich**。
- 播放侧 `fetchUserBdstoken` 三层（baidu_ibox_client.dart:735-763：gettemplatevariable → disk/main 正则 → WebView 正则），**无保存值回退**；空即抛播放错误（:1209-1218）。
- WebView 层只做 HTML 正则（`_webViewBdstoken` :1868-1881），**无 JS 注入提取**——disk/main 的 bdstoken 由 JS 运行时注入，静态正则大概率空手。

### 修复步骤

**改动 1：登录侧 enrich（native_cloud_drive_login_gateway.dart 百度分支，扫码成功后、`_persist` 前）**

```dart
// 伪代码：对齐 iOS baiduEnrichAccountCookie 五端点串行补全
Future<({String cookie, String? bdstoken, String? uk, String? username})>
    _enrichBaiduCookie(String cookie) async {
  var collected = mergeCookieStrings([cookie]);
  const endpoints = <String>[
    'https://www.baidu.com/',
    'https://passport.baidu.com/center',
    'https://pan.baidu.com/disk/main',
    'https://pan.baidu.com/api/gettemplatevariable?clienttype=0&app_id=250528'
        '&web=1&fields=["bdstoken","uk","username"]',
    'https://pan.baidu.com/api/getuinfo?clienttype=0&app_id=250528&web=1',
  ];
  for (final url in endpoints) {
    try {
      final resp = await _http.get(url, headers: {
        'Cookie': collected, 'User-Agent': webUA, 'Referer': 'https://pan.baidu.com/',
      });
      collected = mergeCookieStrings([collected, ...extractSetCookies(resp)]);
      if (url.contains('gettemplatevariable')) {
        // 提取 bdstoken / uk / username（ deep 取 result 字段，对齐 iOS baiduDeepString ）
      }
    } catch (_) { continue; } // 失败静默，不阻断登录（对齐 iOS continue 语义）
  }
  return (cookie: collected, bdstoken: ..., uk: ..., username: ...);
}
```

`_persist` 时：cookie 用补全后的值；`extra` 增加 `bdstoken`、`uk`、`username`（有则存）；statusMessage 保持「百度扫码登录成功，已保存 BDUSS/STOKEN」。

**改动 2：播放侧第 4 层兜底（baidu_ibox_client.dart）**

- `BaiduIBoxClient` 构造/解析入口增加可选参数 `String? savedBdstoken`（由调用方从 `CloudDriveCredentialStore` 读 `credential.extra['bdstoken']` 传入）。
- `fetchUserBdstoken`（:735-763）WebView 层之后追加：

```dart
if (token.isEmpty && (savedBdstoken ?? '').isNotEmpty) return savedBdstoken!;
```

- 活取成功后回写：调用方在拿到新 bdstoken 时 `copyWith(extra: {...extra, 'bdstoken': token, 'bdstoken_source': source})` → `store.save`（对齐 iOS saveBdstokenCredential 4761-4762）。

**改动 3：WebView 层补 JS 提取（in_app_webview_bridge.dart + _webViewBdstoken）**

- `WebViewBridge.loadPage` 协议增加可选 `String? postLoadJs`（或新增 `loadPageAndEvaluate`）：页面加载完成后执行注入脚本并返回结果。
- `_webViewBdstoken` 注入脚本（对齐 BaiduWebViewBridge.swift:146-152）：

```javascript
(function(){
  try { if (window.locals && window.locals.get) return window.locals.get('bdstoken'); } catch(e){}
  try { if (window.context && window.context.bdstoken) return window.context.bdstoken; } catch(e){}
  return null;
})()
```

返回非空即用；为空再走现有 `extractBdstokenFromHTML(page.html)`。

### 验收

- 重扫码登录百度 → 授权中心详情行可见 `extra.bdstoken` 非空。
- 播放百度分享链接 → 不再报「未取得用户态 bdstoken」；`recordRouteDiagnostic` 主路链通过转存段。
- 断网模拟活取失败（改错 Referer 复现）→ 播放仍可用保存值兜底成功。

## 2. P0-B 阿里 refresh_token 刷新落库

### 对齐依据

iOS `refreshAliAccessTokenIfNeeded`（CloudDriveAuthManager.swift:270-339）四层链全落库；Flutter `refreshAccessToken`（aliyun_adrive_client.dart:314-335）两层（官方/WebApp）结果只在内存用（:521、:800 两处调用点），validator 已登记此缺陷（cloud_drive_credential_validator.dart:16-18）。

### 修复步骤

1. `AliyunAdriveClient` 构造函数增加回调：
   ```dart
   AliyunAdriveClient({ ..., this.onTokenRefreshed });
   final void Function(String accessToken, String refreshToken)? onTokenRefreshed;
   ```
   `refreshAccessToken` 成功分支（两层各自 return 前）触发回调。
2. 接线：`PanPlayer`（pan_player.dart:97 构建 `_aliyun`）注入回调 → 读 `cloud_drive_credentials_v1` 的 ali 凭据 → `copyWith(refreshToken: newRefresh /*轮换值优先*/, accessToken: newAccess, updatedAt: now)` → `store.save`。
3. 若当前调用点拿不到 store，允许从 `PanPlayer` 构造参数注入 `CloudDriveCredentialStore`（或经 usecase 传递），保持 datasource 层不反向依赖 presentation。

### 验收

- 播放一次阿里分享资源 → 存储中 ali 凭据 `refreshToken` 与登录时不同（轮换后新值）。
- 连续播放两次 → 第二次用第一次刷新后的 token，无失效报错。

## 3. P0-A 阿里 OpenList 登录（对齐 iOS 主路径）

### 对齐依据（关键结论：iOS「原生扫码」= 可见 WebView + JS 提取）

- `NativeCloudQRLoginView(.ali)` 内嵌 `AliOpenListWebView`（WKWebView 加载 `https://api.oplist.org/?driver=alicloud&driver_txt=alicloud_qr&server_use=true&server_set=true`，CloudDriveAuthManager.swift:2267）。
- 页面加载完 2s 后注入 JS monitor（:2315-2373）：扫描 `input/textarea/[data-token]` 值与页面文本中 ≥50 字符含 `.` 的 refresh_token；MutationObserver + 3s 定时轮询。
- 经 `aliTokenHandler` postMessage 回原生 → `saveAliCredentialIfNew`（去重保存，:240-263）。
- 外层 `pollAliOpenList` 1s 轮询 `isLoggedIn`，上限 180 次（SettingsViews.swift:5000-5014）。
- 纯 API 版 `aliOpenListCreateQr/aliOpenListExchangeToken`（:105-215）为备用路径；WebView 兜底（TokenWebView ali 分支）同一 startUrl，cookie 值写入 refreshToken 字段（:2601-2602）。

### 修复步骤

1. **按钮与路由**：
   - `cloud_drive_widgets.dart` 阿里动作从 `[('PG扫码登录', ...)]` 改为 `[('原生扫码', ...)]`（对齐 iOS providerAccountCard ali 分支文案）。
   - `defaultCloudDriveLoginGateway` 增加 `ali + nativeQr` 支持；`openCloudDriveLoginSheet` 对 `ali + nativeQr` 打开新的 **OpenList WebView 登录 Sheet**（不进 `CloudDriveQrLoginSheet`）。
   - PG 扫码入口从阿里卡片移除（对齐 iOS 隐藏态）；`AliyunPgLoginGateway` 代码保留，extscreen 播放/刷新链不受影响。
2. **OpenList WebView Sheet**（新组件，建议 `aliyun_oplist_login_sheet.dart`）：
   - 可见内嵌 WebView（`InAppWebView`）加载 OpenList startUrl，UA 用移动端（对齐 iOS customUserAgent，:2259）。
   - 页面加载完成 2s 后注入 iOS 同款 JS monitor（可原样移植 :2317-2371，把 `window.webkit.messageHandlers.aliTokenHandler.postMessage` 替换为 `console.log` 约定串或 `onConsoleMessage`/`shouldOverrideUrlLoading` 通道回传 Flutter）。
   - 提取到 refresh_token → `saveAliCredentialIfNew` 语义（同 refreshToken 去重）→ 落 `cloud_drive_credentials_v1`，authType=qr，state=valid，statusMessage「阿里云盘登录成功」。
   - 1s 轮询登录态，成功后自动关 Sheet；关闭/取消时 cleanup（停轮询、停 WebView）。
3. **网页兜底**：`cloud_drive_login.dart` `CloudDriveWebLogin.urls` 登记 `ali → https://api.oplist.org/?driver=alicloud&driver_txt=alicloud_qr&server_use=true&server_set=true`（对齐 TokenWebView ali 分支）；`WebAuthPolicy` 增加 ali 条目（cookieHosts/域名白名单含 oplist.org、alipan.com、aliyundrive.com）；web 保存器对 ali：提取值写入 `refreshToken` 字段而非 cookie（对齐 iOS :2601-2602）。
4. **文案修正**：`cloudDriveNotes[ali]` 改为与实现一致（「OpenList 授权页扫码获取 refresh_token」）。

### 验收

- 阿里卡片点「原生扫码」→ WebView 打开 OpenList 页 → 阿里 App 扫码确认 → 页面出现 token 后 1~3s 内自动保存并关闭，授权中心角标「已获取」。
- 存储中 ali 凭据 refreshToken 非空；播放链（PG 关闭时走 adrive 官方链）可用。

## 4. P1-A 激活百度/夸克/UC 的 Node 扫码入口

### 对齐依据

iOS 三张原生卡内 Segmented 切换原生/Node（SettingsViews.swift `BaiduScanMode` :4421-4427、夸克 :3986-4049、`UCScanMode` :4413-4438）；Node 模式复用 `NodeScanQRLoginView(provider: baidu/quark)`、UC 走 `NodeUcTwoStepLoginView`（NodeLoginViews.swift:1484-1577）。

### Flutter 现状（死代码位置）

- `cloudDriveAuthActions` 已定义 `Node扫码登录` 动作文案但仅用于 `ucNode/baiduNode/quarkNode/one15` 类型（cloud_drive_widgets.dart:62-69）。
- `cloudAuthCenterOrder` 12 张卡不含三张 Node 派生类型（cloud_drive_auth_controller.dart:30-43）→ 按钮永远渲染不出。
- Node 网关/provider 链路完整可用（node_login_gateway.dart:312-341，providers：quark/baidu/ucCookie/ucToken）。

### 修复步骤（两步走）

**第一步（打通可用性，最小改动）**：
1. `cloudDriveAuthActions` 的 baidu/quark/uc 分支各追加 `('Node扫码登录', Icons.phone_iphone)`。
2. 动作分发处（`auth_center._handleAction` 或 `openCloudDriveLoginSheet` 入口）做类型映射：`action == 'Node扫码登录' && type ∈ {baidu, quark, uc}` → 按 `{baidu→baiduNode, quark→quarkNode, uc→ucNode}` 换类型后走既有 nodeQr 路由。uc 命中已有的两步扫码特判（login_sheet.dart:61-66）。
3. 凭据落 Node 命名空间（baiduNode/quarkNode），与本地原生凭据互不影响（对齐 iOS「两条路链互不影响」语义）。

**第二步（UX 完全对齐，可选增强）**：
- `CloudDriveQrLoginSheet` 顶部增加 SegmentedToggle（原生/Node），切换时重建 `CloudDriveLoginController`（换 gateway 与类型）。第一步落地后此步仅为交互形态对齐，可放后。

### 验收

- 百度/夸克/UC 卡片各出现「Node扫码登录」按钮；点击后二维码出现（Node runtime 就绪前提下），扫码成功后凭据写入对应 Node 命名空间，授权中心对应卡（或详情行）可见。
- UC Node 走两步扫码（Cookie → TV Token），第 2 步 TV 链已有实现。

## 5. P1-B UC 原生扫码后 TV Token 跟进

### 对齐依据

iOS：UC 原生扫码成功 → 授权中心自动弹 `UCTVAuthQRView`（SettingsViews.swift:1676-1683）→ `ucStartTVAuth`（:927，open-api-drive.uc.cn）→ `ucPollTVAuth`（:978）→ `ucExchangeTVCode`（:1060，`api.extscreen.com/ucdrive/token`）→ `ucSaveTVToken`（:1118，accessToken/refreshToken 并入 uc 凭据）。动机：非高会账号取流需要 Cookie + TV Token 双凭据。

### Flutter 现状

- 原生 UC 扫码只落 Cookie（native_cloud_drive_login_gateway.dart:169-300），无 TV 跟进。
- TV Token 链仅在 ucNode 两步扫码（走 Node provider `ucToken`），无 extscreen 直连版。
- validator 已认「cookie 或 TV Token 任一非空」（cloud_drive_credential_validator.dart:318-325）——存储结构无需变更。

### 修复步骤

1. `native_cloud_drive_login_gateway.dart` 新增 `ucTvAuth` 网关方法（对齐 iOS 三段：start/poll/exchange，端点 open-api-drive.uc.cn + `api.extscreen.com/ucdrive/token`），成功后把 accessToken/refreshToken 并入 uc 凭据（`copyWith`，保留 cookie）。
2. UI 接线：`CloudDriveQrLoginSheet`（uc + nativeQr）扫码成功回调后自动切换到「TV 授权」态（复用 `CloudDriveUcTwoStepQrSheet` 的两步 UI 骨架：第 1 步显示「Cookie 已完成」，直接进第 2 步 TV 授权；对齐 iOS 自动弹窗行为）。
3. TV 授权失败/跳过不回滚 Cookie 凭据（对齐 iOS 宽松语义）。

### 验收

- 原生扫码 UC 成功后自动进入 TV 授权；完成后 uc 凭据 `cookie` 与 `accessToken/refreshToken` 同时非空；非高会账号可取流播放。

## 8. 风险与注意事项

- `in_app_webview_bridge.dart` 自述「未经编译验证」（:16-18）：P0-A / P0-C 改动 3 均依赖它，落地前先跑一次 `flutter analyze` + 真机 headless webview 冒烟（Android 先行）。
- P0-C 改动 1 的五端点 enrich 与 iOS 一致为「只读、单次串行、失败静默」，不得加重试循环，避免触发风控。
- P0-A 落地后 `CloudDriveWebLogin.urls` 的 ali 条目与 OpenList Sheet 并存：Sheet 失败时用户仍可从「网页登录兜底」进入同一页面手动复制 token，双保险。
- 所有改动保持文件头「对齐 iOS xxx（行号）」注释惯例，便于后续重扫核对。
- 测试：为 P0-C（enrich + 兜底回退）、P0-B（刷新落库）、P1-A（类型映射路由）补单测（fake 网关/store 模式已有先例：test/presentation 与 test/data 下）。
