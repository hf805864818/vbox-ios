## 0. 版本变更（v1.2 → v1.3）· 一处必须纠正的归类错误

### 0.1 触发本轮的质疑

v1.2 §6 把 iOS 的 **MPVKit / MoltenVK / MDK / VT 渲染后端**与 **AliyunPlayer SDK**、**DoubanImageProxyServer** 一并列为「iOS 平台专属（不移植，仅记录）」，理由是"Flutter 四端用各自等价方案"。

**这个结论在方向上对、在判定上错**：Flutter 端确实用了各平台等价**解码器**（Android Media3 / Windows libmpv / macOS AVPlayer），但**等价方案只落地了「控制面」，没有落地「渲染显示面」**。因此把它们记作"不移植且已等价"属于**严重低估**。

### 0.2 核心复核结论（一句话）

> **播放控制面（open/play/pause/seek/volume/speed + state/progress 事件）四端齐备；播放渲染面（把画面显示出来）四端皆空。** 用户当前"能听声、看不见画面"。

## 1. 本轮追踪方法（显示/渲染链路）

对「播放」与「封面图」各做一次**从 UI → 平台通道 → 原生 → 输出面**的端到端追踪：

```
播放链路：
  UI（点「播放」）→ PlayerController.open() → ChannelPlayer（MethodChannel）
    → 原生 PlayerPlugin（Windows .cpp / macOS .swift / Android .kt）
      → 解码器（libmpv / AVPlayer / Media3）
        → ★ 渲染输出面（Texture / Surface / RenderView）  ← 本轮重点核查对象
封面图链路：
  PlatformAsyncImage → 防盗链头注入 → Image.network / Image.memory
    → ★ 是否 403（豆瓣/TMDB 防盗链）  ← 本轮重点核查对象
```

### 2.3 与 iOS 的对照（为何这叫"缺口"而非"平台差异"）

iOS 侧「渲染」是一等公民，且每引擎都配**独立渲染视图**：

| iOS 渲染资产（`vbox/PlayerCore/` + `vbox/Views/`） | 作用 |
|---|---|
| `MPVKitMetalLayer.swift` · `MPVKitRenderView.swift` · `MPVKitRenderedPlayerCore.swift` | MPVKit 的 **Metal 渲染视图** |
| `LibmpvMoltenVKPlayerCore.swift` | libmpv + **MoltenVK** 渲染 |
| `MDKRenderView.swift` · `MDKPlayerEngine.swift` · `MDKPipManager.swift` | MDK 渲染 + PiP |
| `PlayerViewsV2.swift`（**11238 行**） | 多引擎切换 + `AliPlayerRepresentable` / 各 RenderView + PiP 编排 |
| `PlayerEngineType.swift` | 5 引擎：`system` / `vlc` / `mpvKit` / `libmpv` / `mdk` |

> **判定**：Flutter 用「Media3 / libmpv / AVPlayer」替代「MPVKit / MDK / VT」**命名**是合理的（跨平台等价解码器）；但**必须补齐的是「渲染输出面」这一能力本身**——而它目前是空的。因此该能力**不得**计入"已对齐"，也**不得**计为"平台专有不移植"。

### 2.4 计划书口径的落差

计划书（`VBOX_PLAN_v6.51.md`）把播放记为 **G-02「部分解除」**：
- `G-02-A`：Dart 抽象 + 平台通道桥 + Android Gradle 接线 ✅
- `G-02-B-1`：macOS **AVPlayer 接线** ✅（复杂封装返回 `E_BACKEND_UNAVAILABLE` 供降级链捕获）
- `D28`：libmpv 原生二进制**不入 git**，由脚本从 GitHub Release 下载，随 DMG/EXE 分发
- `G-02-C`：端到端回退**真机验收**；E.10b 余项 = `G-02-C / G-05 / G-09 / G-10`

> **落差**：计划书以"控制面 + 降级链语义"为交付粒度，故记"部分解除"；但以**用户可感知验收标准（能否看到画面）**衡量，四端**均未交付**。本版据此将"渲染层"单列为**最高优先级缺口**，建议新增编号 **G-02-R（Render）**，明确其验收标准 = **四端均可显示视频画面且复杂封装可回退**。

## 3. 核心复核 A2 · 封面图（豆瓣/TMDB）—— 不是缺口（结论修正而非新增）

### 3.1 原结论的问题

v1.2 写"Flutter **直连**豆瓣图片 URL"。**直连必然 403**（豆瓣/TMDB CDN 防盗链），该表述不准确。

### 3.2 实测：Flutter 已用「请求头注入」等价替代 iOS 的「本地代理」

`lib/presentation/widgets/platform_async_image.dart` 完整实现了防盗链破解（**与 iOS `DoubanImageProxyServer.fetchImage` 语义等价**）：

| 能力 | iOS 做法 | Flutter 做法（实测） | 对齐 |
|---|---|---|---|
| 豆瓣/TMDB 防盗链头 | 本地 HTTP 代理注入 `Referer: https://movie.douban.com/` + UA + Accept | `Image.network(headers:)` 命中主机自动注入（`:194-206`，`kDoubanImageHosts` 13 主机） | ✅ |
| TVBox `@key=value` 后缀（spider `pic` 常见） | 拆出干净 URL + 头 | `parseHeaderSuffix`（`:143-157`） | ✅ |
| `data:` 内嵌图 | `loadDataImage` | `_embeddedDataImage` → `Image.memory`（`:128-137`） | ✅ |
| SSL 绕过 | `WelfareSSLBypassDelegate` | `_SslBypassImage`（`badCertificateCallback` 全放行，`:293-370`） | ✅ |
| `http://` → `https://` 升迁 | 有 | `coverFor`（`:115-123`） | ✅ |
| 缓存 | `NSCache`（内存，`countLimit=300` / 80MB） | `PaintingBinding.imageCache`（内存） | ✅（**两侧均无磁盘缓存**） |

> **判定**：封面图**不是缺口**——Flutter 无需移植"本地 HTTP 代理服务器"这一实现形态，功能已通过请求头注入对齐。v1.2 §6 该行的"直连"描述须改为"**请求头注入（等价）**"。

### 3.3 但需注意：iOS 代理 ≠ 仅图片代理（职责映射待核对）

`vbox/Services/DoubanImageProxyServer.swift` 实测 **3291 行**，是一个**综合本地 HTTP 代理**，除图片外还含：
- `BaiduStreamSegmentCache`（百度网盘**流式分片缓存** + 进度通知）
- 百度 PCS UserAgent（`netdisk;1.4.2;...`）
- m3u8 代理（`Content-Type: application/vnd.apple.mpegurl`）

Flutter 侧这部分职责由 **Go 代理**承担：`go-proxy/`（`package quarkproxy`：`cache.go` **磁盘** `DiskCache` · `m3u8.go` · `proxy.go` 路由 `/quark-m3u8/play` · `/quark-stream/play` · `/seg`）+ `lib/platform/player/go_proxy_client.dart` + 三端插件。

> ⚠️ **待核对**：go-proxy 实测为 **夸克（quark）**流代理，**未见百度分支**；而 iOS 代理内含**百度**分片缓存。此项与 §4 的网盘直链缺口**同源**，见 §4。

## 4. 新增缺口 A4 · 网盘「原生直链播放」未接线

### 4.1 实测

`lib/platform/player/pan_player.dart` 的路由判定（`:74-83`）：

| 盘类型 | 通道 | 状态 |
|---|---|---|
| Node 托管（UC / 百度网盘 Node） | `PanPlayChannel.nodePan` | ✅ 走 Node 常驻链路 |
| 阿里 | `PanPlayChannel.pgAli` | ✅ |
| **夸克 / 百度 / UC（原生直链）** | `PanPlayChannel.native` | ❌ **`:14`「原生路链（待后续批次接线，本批次明确报错）」** |

### 4.2 对照 iOS

iOS 网盘播放依赖本地代理（`DoubanImageProxyServer` 内 `127.0.0.1:18080` 流代理）把网盘文件转成 HTTP 流再交给播放器；`PlayerViewsV2.swift:1299-1303` 明载"**云盘本地代理 URL（127.0.0.1:18080）**"。

Flutter 的替代是 Go 代理，但**仅覆盖夸克**；**百度/UC 原生盘未接线**。
（注：`lib/data/datasources/remote/baidu_proxy_client.dart` 是**接口调用层**——Cloudflare Worker + HMAC-SHA256 签名 + PCS 设备指纹——**不是播放流代理**，不可与 iOS 的流分片缓存混同。）

> **判定**：这是"播放视频"的一个**真实子缺口**，记为 **F-补·网盘原生直链播放链路**（含百度流分片缓存，双向核对 go-proxy）。

1. **「对齐」= 功能语义等价**，非文件 1:1。
2. **「缺」= 连语义等价物都没有**。
3. **「部分」= 有底座/契约键但缺关键片段**。
4. **「口径」= 需先定对齐边界**。
5. **v1.2 门槛**：追加判「**是否可达**」（存在但零引用仍记"部分/缺"）。
6. **v1.3 门槛（本轮新增）**：追加判「**输出面是否可见**」——**控制面/解码器存在不算对齐；必须"用户能感知"（画面可显示）方记为对齐**。据此，播放能力在四端**全部**重判为未交付。
