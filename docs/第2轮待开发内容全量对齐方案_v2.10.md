# vbox 第 2 轮 · 待开发内容全量对齐方案 v2.10（浮层组件 + 系统能力专项补扫版）

> **版本**：v2.10 —— 在 [v2.9](computer:///workspace/docs/第2轮待开发内容全量对齐方案_v2.9.md) 基础上，执行 **第 15 方向：浮层组件接线审计 + 系统能力集成（画中画/后台播放/屏幕常亮/网络监测/触感反馈入口）+ 辅助功能**，这三类是「组件已建但**没接线**」或「平台层就绪但**UI 未消费**」的隐藏遗漏。
> **核心原则（写入文档，全篇强制）**：**UI 层的开发一律以 iOS 端为准**——参考依据为 `docs/ui_baseline/ios_ref/` 35 张真机截图 + `vbox/Views/` 54 个 Swift 源码文件；凡 UI 形态、交互、组件结构有争议，一律回到 iOS 基准实测值裁决，不允许凭 Flutter 习惯自由发挥。
> **核对日期**：2026-10-04

## 0. 本轮四大新发现（65 → 69 项）

### 🔴 UI-D1 · RemoteSourceStatusBar 未接入壳层（P1）

iOS `ContentView.swift:90-91` 挂载了两个全局浮层：`RemoteSourceStatusBar()` + `DownloadCapsuleNotification()`。Flutter **只接了后者**（`home_shell_page.dart:99`），**RemoteSourceStatusBar 全端 0 处接入**——虽然 `domain/entities/remote_source/` 数据层和 `welfare_settings_page` 里都有展示，但**壳层浮层没有**。iOS 的 RemoteSourceStatusBar 是带跑马灯（`MarqueeText`）的全局状态条，用于提示远程源同步进度/失败。

### 🔴 UI-D2 · 屏幕常亮 wakelock 全端零引用（P1）

iOS `PlayerViewsV2.swift` **10 处** `UIApplication.shared.isIdleTimerDisabled = true/false`（播放中常亮、暂停恢复、离开页面关闭）；漫画阅读器 `MangaReaderView` 同样需要常亮。Flutter `wakelock` 全仓 **0 引用**——播放器播放中不常亮、漫画阅读不常亮，是**已交付播放器/漫画的实际行为缺陷**。

### 🟡 UI-D3 · 画中画 PiP 平台层就绪但 UI 未接线（P2）

Flutter `platform/player/pip/` 下已有完整 PiP 栈（`pip.dart` / `pip_controller.dart` / `pip_strategy.dart` / `background_play.dart` / `floating_window.dart`），iOS `PlayerViewsV2`/`AliPlayerRepresentable`/`DownloadOverlayViews` 都有 PiP 入口。但 **`player_controls_view.dart` / `player_top_bar.dart` 的 `onCast`/`onPiP` 回调未接 PiP 平台调用**——按钮存在、点不动。

### 🟡 UI-D4 · 辅助功能 Semantics 覆盖极低（P3）

iOS `ProfileView.swift` 有 `accessibilityLabel`；Flutter 全仓 Semantics 仅 **3 处**（`vbox_welfare.dart` / `vbox_skin_picker.dart` / `vbox_nav.dart`），关键交互组件（海报卡片/视频卡片/播放器按钮/Tab 栏）基本无语义标签。TalkBack/VoiceOver 可用性差。
