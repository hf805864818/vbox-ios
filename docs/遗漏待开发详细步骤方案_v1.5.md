# vbox 遗漏待开发详细步骤方案 v1.5

> **版本**：v1.5 —— 在 [v1.4](computer:///workspace/docs/遗漏待开发详细步骤方案_v1.4.md)（248 项）基础上做**第 26 轮（第 5 次全面）分析**：7 大域并行深挖（播放内核/网盘与下载与漫画/音乐与直播与短剧与豆瓣与TMDB/福利域/特色内容平台/设置与基建/蜘蛛引擎与站源），并对 v1.0~v1.4 已登记条目做**全量去重**。净新增 **22 项** + **3 处勘误** + **14 项不需对齐确认**。
> **核对日期**：2026-10-05（基于 main 最新代码 + 7 大域文件级比对）
> **核心原则（强制）**：UI 层一律以 iOS 端为准（35 张真机截图 + 54 个 Swift 源码）。

> **本轮最重要发现**：大量此前登记的「平台/页面缺失」本轮复核 **已登记且数据层已就绪，真正的断点是"接线缺失"**——数据/服务层已交付（zhanyuan_search、tencent_video_spider、ExtscreenApiClient、FuliBaseService 骨架等），但 **presentation/控制器链路未接线**，导致「已开发未对齐 iOS」。这轮把这类「接线缺口」作为重点新登记。

## 1. P-芯 · 播放内核 / 路由 / 字幕 （7 项）

> 全为「已开发但缺模型/断点/接线」的深化。已登记不重复：进度续播(Pcore-D1)、生命周期(Pcore-D2)、PiP承载(Pcore-D3)、转封装内置解析(Pcore-D4)、事件面(Pcore-D5)、锁屏(Pcore-D6)。

### 🔴 P-芯1 · 播放路由模型粒度不对齐（缺 type/url/headers/priority）— P1

**问题**：iOS `PlaybackRoute{ type,url,headers,title,priority }`（PlaybackRoute.swift:5-31）能表达"多条候选线路 + 优先级 + 每线路鉴权头"；Flutter `PlaybackRoute` 仅 `detail/live/pan/music/local` 语义分类（playback_route.dart:10-25，**无 url/headers/priority**），且其注释误引不存在的 iOS `PlayerRouteResolver`。线路排序/原画 vs 流畅/localProxy 均无模型支撑。

**步骤**：给 `PlaybackRoute` 增补 `type/url/headers/priority`（或新增 `PlaybackRouteItem`），解析器产出按 priority 排序的候选集；修正注释误引。
**验收**：可传多条候选线路并按优先级选择；headers 随选中线路下发原生。

### 🔴 P-芯2 · PlayerController 缺用户态内核切换 API — P1（R-01 深化）

**问题**：iOS `PlayerEngineController.switchEngine`（:72-105）+ 内核按钮（PlayerViewsV2.swift:8296）；Flutter `player_controller.dart:196-205` 仅失败降级链，**全类无 `switchBackend`**，`onSelectBackend` 在 production 无接线（grep `switchBackend` 0 命中）——内核选择面板无法真正生效。

**步骤**：`PlayerController` 增 `switchBackend(PlayerBackend)`（重建 ChannelPlayer、以当前 PlayerSource 重开）；页面把 `onSelectBackend` 接到该方法。
**验收**：播放中切换内核后继续播放当前资源；`backend` getter 更新。

### 🔴 P-芯3 · 转封装代理丢弃上游鉴权头（确定性 bug）— P2

**问题**：iOS `RemuxProxyServer.registerStream(url:headers:provider:)` 逐头写入上游请求（:119,226-229）；Flutter `remux_proxy.dart:263-266` 调 `RemuxPlan.decide` **未传 headers**，`upstreamHeaders` 恒空（:45），`GET /remux?src=` 无法安全携带 header（:315-321）——需 Cookie/Referer 的受保护流经代理必失败。

**步骤**：改为 id 注册模型（本地注册表按 id 存 headers），`/remux` 用 id 取流并注入上游请求。
**验收**：带 Cookie/Referer 的受保护流可经代理正常转封装播放。

### P-芯4 · 字幕 SSA 识别 + ASS 样式标签剥离 — P2（UI-F5 细化）

**问题**：iOS `SubtitleParser` 识别 `.ssa`（:64-72）+ `cleanASSText` 剥离 `{\...}`/`\h`（:295-307）；Flutter `sniff` 不认 `[V4 Styles]`（SSA 返回空，subtitle_parser.dart:62-76）、`parseAss` 未剥离 `{\...}`（:153-183）。

**步骤**：`sniff` 增 `[V4 Styles]`；`parseAss` 增 `{\...}` 剥离与 `\h` 处理。
**验收**：SSA 可解析；ASS 渲染文本不含样式标签。

### P-芯5 · 字幕无文件加载与编码兜底 — P3（UI-F5 细化）

**问题**：iOS `parse(url:)` 依次 UTF-8 → unicode → utf16（SubtitleParser.swift:28-39）；Flutter 仅 `parseAuto(String)` 无字节解码/文件入口（subtitle_parser.dart:51-59,79,107,153）。

**步骤**：增 `parseBytes(Uint8List)`（UTF-8/BOM/UTF-16 嗅探）+ 文件/URL 加载助手。
**验收**：UTF-16 字幕可正确解析。

### P-芯6 · 后端能力元数据未内聚 — P3

**问题**：iOS `PlayerEngineType` 内聚 `displayName` + `supportsPiP`（:13-40）；Flutter `PlayerBackend` 无元数据，显示名重复散落 engine_picker_panel.dart:73-78 与 player_controls_controller.dart:173-182，PiP 按策略非后端判定。

**步骤**：在 `PlayerBackend` 内聚 `displayName/supportsSystemPip`。
**验收**：后端能力单点可查，UI 无重复文案表。

### P-芯7 · PiP 缺「仅后台声音」降级策略 — P2（Pcore-D3 细化）

**问题**：iOS `PiPStrategy` 含 `backgroundAudioOnly`（PlayerViewsV2.swift:806-825）：系统 PiP 不可用且后台播放开启时退化为纯音频后台（:8461-8467）；Flutter `PipStrategy` 无此语义，`PipController.enter` 在 none 时直接 `return false`（pip_controller.dart:89-111）。

**步骤**：`PipStrategy` 增 `backgroundAudioOnly`；`PipController` 在系统 PiP 不可用且 backgroundPlay 开时改触发 BackgroundPlayController。
**验收**：系统 PiP 不可用且后台播放开启时，退后台仍保留声音。

## 2. C-盘 · 网盘 / 云盘 （3 项）

> 已登记不重复：原生盘播放链路(F-P09/F-08)、Node 系列登录(F-P16)、网页登录 WebView(Web-R1~R5)、网盘资源下载(Down-M2)、TS→MP4(Down-M3)、PG 4kz 播放编排(F-P09/D28 口径)。

### 🔴 C-盘1 · PG 阿里云盘扫码登录未接线（数据层已交付）— P1

**问题**：iOS `AliyunPgAuthManager` 完整 `startQrLogin`（getQrcode→poll→getRefreshToken→refresh→落库）；Flutter `ExtscreenApiClient` 全链已实现（aliyun_extscreen_client.dart:85-310）但**零消费者**；`ali` 授权按钮映射到 `nativeQr` 而非 `pgQr`（cloud_drive_widgets.dart:41-43 + cloud_drive_login.dart:79-87），`CloudDriveLoginMode.pgQr` 为死代码。

**步骤**：新增 `AliyunPgLoginGateway`（pgQr 分支）串联 `ExtscreenApiClient`；成功后写 `cloud_drive_credentials_v1`；`ali` 按钮文案改「PG扫码登录」。
**验收**：阿里云盘授权中心可 PG 扫码、阶段推进、凭据落库、卡片显示「已登录」。

### C-盘2 · 网盘文件列表页未接线 + 无真实 lister — P2

**问题**：Flutter `CloudDriveFilesPage/files_controller.dart` 已具备清理队列，但 `CloudDriveFileLister` 缺省为 `UnavailableCloudDriveFileLister`（files_controller.dart:29-40,61），全仓无真实实现；`CloudDriveFilesPage` 除自身外无任何导航入口（pages.dart:6 仅导出）。

**步骤**：实现各盘 `CloudDriveFileLister`；在云盘入口/播放器挂载 `CloudDriveFilesPage`。
**验收**：云盘入口可进文件列表，选文件转存出现在清理队列，到期可清理。

### C-盘3 · 本地二维码编码能力缺失（PG 返回授权链接非图片）— P2

**问题**：iOS `AliyunPgQrLoginView.swift:104-118` 由链接本地生成二维码；Flutter 契约只承载图片型 `qrDataUrl`（login_gateway.dart:16），`ExtscreenApiClient.getQrcode` 返回的是 `qrLink`，pubspec 无 qr 编码依赖——即便 C-盘1 接线也无法渲染。

**步骤**：引入二维码编码依赖或网关转图像，把 `qrLink` 转可渲染。
**验收**：PG 扫码登录页能显示由 `qrLink` 生成的二维码。

**验收**：选集确认后福利视频进入下载队列，可在下载管理中查看。

### W-福5 · `parse=1` 播放地址二次解析桥缺失 — P2

**问题**：iOS `SpiderManager.parsePlayUrl`（直链提取 + WKWebView 回退，FuliVideoBridgeView.swift:411-481）；Flutter `welfare_video_bridge_page.dart:181-192` 直接取 `fetchPlayerURL` 返回地址，未对 `FuliPlayerResult.parse==1` 二次解析。

### W-福6 · 域名/代理变更未触发 Service 重探测 — P2

### W-福7 · 漫画图片数据链：JS 蜘蛛不加载漫画图片 — P1

**验收**：JS 与 Python 漫画平台均能解析 `images` 并被阅读器消费。

### W-福8 · 设置页「远程源状态」未展示版本号与上次成功时间 — P3

**问题**：iOS `RemoteWelfareSettingsView.swift:174-184` loaded 态展示 version/上次成功时间；Flutter `welfare_settings_page.dart:323-386` 的 `_statusSection` 仅取 `errorMessage`，控制器已有 `lastSuccessTimeSeconds/lastConfigVersion`（welfare_platform_controller.dart:103-107）却未渲染。

## 4. S-设 · 蜘蛛 / 搜索 / 基建 （4 项）

> 全为「底层已实现、presentation 未接线」的接线缺口。

### 🔴 S-设1 · 本地插件脚本暂未接线（JS/Python 一律抛错）— P1

**问题**：iOS `SpiderManager.loadCustomParsers` + JSSpiderEngine 支持本地 .js 插件（:289）；Flutter `content_browse_usecases.dart:409-412` 对非 http(s) 脚本一律 `UnsupportedFailure('本地插件脚本暂未接线（本批仅支持 http(s) 脚本 URL）')`，覆盖 quickJS 与 python 两引擎（:402-403）、影响 home/category/search/content 全路径。

**步骤**：为 quickJS/python 引擎补本地脚本加载路径（读缓存脚本字符串非仅 URL），复用 `engine.loadLibrary` + `registerSpider`。
**验收**：配置本地 .js/.py 脚本地址的站源可首页/搜索/详情，不再抛本地插件异常。

### 🔴 S-设2 · 占源搜索未接线 — P1

**问题**：`ZhanyuanSearchUseCases.searchAll` 已实现（zhanyuan_search_usecases.dart:45）+ `zhanyuan_search_service.dart:114` 已实现，但 grep `searchAll` 无任何 presentation/controller 调用方——搜索页未走占源并列搜索。

**步骤**：在 Flutter 搜索页串联 `ZhanyuanSearchUseCases.searchAll`，复用服务层，补结果分批回调。
**验收**：搜索页触发并列站源搜索并展示各站源结果。

### 🔴 S-设3 · 腾讯视频原生蜘蛛未接线 — P1（E-7 深化）

**问题**：iOS `TencentVideoNativeSpider` 已在搜索/详情全接线（SpiderManager.swift:1828,2575,2640）（替代失效 JS 蜘蛛）；Flutter `TencentVideoNativeSpider` 类已实现（tencent_video_spider.dart:20）但 **无调用方**。

**步骤**：在搜索与详情用例按 iOS 策略（快照/失效检测）接入 `TencentVideoNativeSpider`。
**验收**：Flutter 搜索/详情对腾讯视频站源走原生蜘蛛并返回结果。

### S-设4 · 网络日志缺全局拦截层 / 网络分类 — P2

**问题**：iOS `NetworkLoggerURLProtocol` 全局拦截自定义 URLSession 并统计（NetworkLogger.swift）；Flutter `http_client.dart:150-190` 每请求逐条 `AppLog.debug/warn/error` 打点，无 iOS URLProtocol 等价的全局拦截，日志条目无 `network` 独立 category（LogEntry 仅 tag 字段）。

**步骤**：网络打点收敛到网络日志门控；日志条目增「网络」类别/过滤入口。
**验收**：网络类日志可独立开关与筛选。
