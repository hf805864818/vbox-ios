## 一、勘误（四处与 iOS 不符，已按 iOS 为准订正）

> v1.1 记录勘误 1 / 2；**v1.2 增补勘误 3 / 4**。

### 勘误 1 · R-01「引入 media_kit」→ 实为 **MDK**
v1.0 的 R-01 写「`pubspec.yaml` 添加 `media_kit`」，与既定内核决策冲突：

- **MDK 一统四端**为已拍板决策（弃用「Windows libmpv + macOS AVPlayer + Android Media3/libVLC」异构拼装）；
- iOS 侧 `swift-mdk` **已在生产**（复杂封装首选内核）；四端对应产物为 Android `.aar` / Windows `.dll` / macOS `.framework`；
- 现状：Flutter 侧 **无任何 MDK / media_kit 依赖**，播放全部走原生通道。

**处置**：R-01 重写为「MDK 内核接入」，完整步骤见 **第四节**。

### 勘误 2 · UI-F19「倍速档位补 3.0x」→ **取消**
- iOS 常规倍速面板最高 **2.0**（Swift 侧 `speeds: [0.5, 0.75, 1.0, 1.25, 1.5, 2.0]`）；
- `3.0` 只存在于**长按倍速**面板（`[1.5, 2.0, 2.5, 3.0]`），Flutter 侧 `kLongPressSpeedOptions` 已交付。

**处置**：**不实现**。常规倍速面板保持 6 档，避免偏离 iOS 基准。

### 勘误 3 · R-04「清晰度从 `vod_play_url` 拆分多线路」→ 实为 **固定三档 + 按 URL 探测**（v1.2 新增）

原方案（v3.0 §R-04）写「从 `vod_play_url` 拆分多线路 → `qualities` 列表 → 面板选择」，与 iOS 实现不符：

- iOS `QualityPickerPanelV2.qualities` 为**硬编码固定标签** `["标清", "高清", "蓝光"]`（百度源模式为 `["原画"]`），**并非**从播放地址拆分；
- iOS `PlayerState.changeQuality(index:)` **只改 `selectedQuality` 索引，不重开播放源**（百度源另有明确日志：「暂不支持转码清晰度切换」）；
- iOS `detectVideoQuality(from:)` 按 URL 特征词**探测初始档位**：蓝光/`bd`/`bluray`/`2160`/`4k`/`uhd` → 2；高清/`1080`/`超清`/`hd`/`fhd`/`full` → 1；标清/`720`/`480`/`360`/`sd`/`low` → 0；未命中不改动。

**处置**：第 3 批**已按 iOS 实现**（`kDefaultQualities` + `detectQualityIndex`，落点 `lib/presentation/widgets/player/player_controls_controller.dart`）。原「拆线路」表述作废。

### 勘误 4 · UI-F9「控制栏 **3 秒**自动隐藏」→ 实为 **5 秒**（v1.2 新增）

- iOS 主控制栏为 **5s**（`resetAutoHideTimer` → `Task.sleep(5_000_000_000)`）；
- **3s** 只属**锁按钮**（`resetLockButtonAutoHide`，与主控制栏解耦）；
- Flutter 现状 `_autoHideDelay = 5s` / `_lockHideDelay = 3s`，**与 iOS 完全一致**。

**处置**：**无需改动**。原方案「改成 3 秒」的表述作废。

### 2.4 UI-F17 · 下一集预加载 — ✅ 本版交付（含范围勘误）

**现状（开发中实测）**：全仓原无「下一集预取」实现。**关键发现**：Flutter 侧**网盘路径目前没有剧集列表** —— `detail_page.dart` 的 `_playPanLink`（单条直链）与 `pages/cloud/files.dart`（单文件点播）构造 `PlayerPage` 时**均未传 `episodes` / `onResolveEpisode`**，故「针对网盘做预加载」在当前代码里没有消费方（会成死代码）。

**处置**：把同一机制落在**当前真正存在剧集列表的路径**（详情页蜘蛛多集），实现为通用预取；网盘路径待 **F-P25（网盘文件列表页）/ F-P09（百度多文件选集）** 落地后自动受益，无需再改播放页。

**已实现**：
1. 播放页在剩余 **≤ 30 秒** 时预取下一集直链（`_maybePreloadNextEpisode`）
2. 预取结果缓存（`_preloadedEpisodeIndex` / `_preloadedSource`），**双守卫**防重复触发
3. 切集命中缓存 → **跳过二次解析**（`_playEpisode` 优先取缓存）
4. 预取失败 / 期间已切集 → 丢弃缓存，静默降级为常规解析（不影响当前播放）

**验收**：剩余 > 30s 不预取；进入 30s 内仅预取一次；切集命中缓存不重复解析；预取失败可正常回落。全部用例已通过。

**遗留**：仅当 `episodes` + `onResolveEpisode` 存在时生效。本版已为**网盘分享路径**补上剧集列表（见 3.5），故该路径已可命中预取；详情页网盘单链（`_playPanLink`）与目录模式仍为单文件播放，天然不触发。

### 2.5 UI-F21 · 网盘兜底链（403 / 断连 / 首帧超时 → m3u8）— ❌ 未实现

**现状**：
- `pan_player.dart` 各原生盘失败直接 `throw PanPlayException`，**无兜底链**；
- 播放页仅有**转封装**补救（换容器为 fMP4），与「403 / 断连 / 首帧超时」判据无关；
- `.m3u8` 仅在网盘文件页**主动注册** Go 代理，属正常路径而非失败兜底。

**开发步骤**：
1. 新增 `PanFallbackChain`（对齐 iOS 的 `fallbackURL` / `fallbackHeaders` / `fallbackSource` / `attempted` / 超时任务语义）
2. 判据接入：原画 403 / 连接中断 / **首帧超时** → 自动切 m3u8 兜底
3. 兜底失败 → 回退错误视图（UI-F10 三件套）
4. **需补「首帧超时」事件源**：播放通道现仅有 `state / progress / videoSize / error` 四类事件，需新增首帧 / 卡顿一等事件或超时计时器

**验收**：原画 403 / 断连 / 首帧超时可自动回落 m3u8 并恢复播放；兜底全失败出错误视图。
**规模**：中大（含通道事件扩展）。

### 2.6 UI-F22 · 前后台恢复保护 — ✅ 已交付（v1.2 补记）

**现状核对（代码级实测）**：Flutter 侧 `didChangeAppLifecycleState` **仅**驱动「后台播放承载（C-05）」与「画中画生命周期」；**缺** iOS 的「退后台暂停 + 强制落库 + 回前台宽限恢复」三件事。原描述的「watchdog 队列」经核对实为 iOS `startPlaybackWatchdog`——一个**加载态看门狗**（就绪/播放中但 `isLoading` 仍为 true → 自动清除），非前后台队列。

**本版对齐 iOS 交付**（[PlayerViewsV2.swift:2756 / 2813](<../vbox/Views/PlayerViewsV2.swift#L2756-L2852>)）：

| 行为 | iOS | Flutter 实现 |
|---|---|---|
| 退后台暂停 | `handleSceneBackground`：`!backgroundPlay` → `player.pause()`（iOS 把 `.background` 与 `.inactive` **一并**视为退后台） | `_handleEnterBackground`：`!_playback.backgroundPlay && _controls.isPlaying` → `pause()` |
| 退后台强制落库 | 后台队列强制写进度（`> 5s` 守卫 + 距结尾 `< 15s` 清除） | `_persistProgress(..., throttle: false)`（跳过节流，保留两守卫） |
| 回前台恢复 | `handleSceneForeground`：**800ms 宽限**后 `player.play()` | `_handleEnterForeground`：`Timer(800ms)` → `play()` |

> **有意差异（比 iOS 更保守，已登记）**：Flutter **仅恢复「因退后台被自动暂停」的播放**（`_pausedForBackground` 标记）；用户主动暂停后切后台再回前台**不会**被自动起播。iOS 无此标记，会无条件 `play()`。

**测试**：`test/presentation/pages/player/player_page_lifecycle_test.dart`（4 用例：暂停+强制落库 / 后台播放开启不暂停 / 回前台 800ms 恢复 / 未因后台暂停则不恢复）。

**遗留**：iOS 的 `startPlaybackWatchdog`（加载态 2s 轮询自愈）**未移植** —— 现由 UI-F18 的「首帧尺寸 / 播放态 / 进度回执」三点收起加载层覆盖，暂无重复实现的必要。

| 后端枚举 | `PlayerBackend{media3, libVLC, libmpv, nativeiOS}` |
| 平台链 | `PlayerBackendSelector.chainFor`：Android `[media3, libVLC]` · Windows/macOS `[libmpv]` · iOS `[nativeiOS]` |
| 编排 | `PlayerController` 逐后端尝试，失败自动降级且**降级可观测** |
| 通道 | `com.vbox.player/player`（open / play / pause / seekTo / setVolume / setSpeed / dispose）+ 事件通道（state / progress / videoSize / error）|
| 渲染面 | **所有后端写同一个 Flutter 纹理**（Android `TextureRegistry.SurfaceProducer`；Windows mpv render API；macOS 同构）|

**结论**：新增 MDK = 往这条链插一个新后端，**UI / 控制层零改动**。

### 4.2 M1 · Dart 侧 — ✅ **已交付（v1.1）· v1.2 实测验证**

1. `PlayerBackend` 新增 `mdk`，并补后端元数据：`displayName = 'MDK（全格式）'`、`shortName = 'MDK'`、`supportsSystemPip = false`
2. `chainFor` 调链（**链首保持默认主后端，默认路径不经过 MDK**）：
   - Android：`[media3, mdk, libVLC]`
   - Windows / macOS：`[libmpv, mdk]`
3. `PlayerBackendSelector.initialBackend(chain:, needsFullFormat:)`：「需全格式 → **MDK 优先** → VLC / mpv → 链首」
4. 内核面板自动出现 MDK 项（数据源即 `availableBackends`，无需改 UI）
5. 单测：枚举元数据 · 各端链路 · 优先选择 · 降级顺序（`test/platform/player/player_backend_selector_test.dart`）

**原生未接入时的行为**：`open(backend: mdk)` 由原生回 `E_BACKEND_UNAVAILABLE` → 编排按链自动降级到下一后端，**与现状行为完全一致**（零风险，可先行上线）。

**v1.2 实测验证**：`flutter analyze` 0 issue · `flutter test` **全量通过** · UI 令牌 / Dart 导入 / 契约同步 / 平台接线 **四项守卫全绿**。

**验收**：Dart 侧全绿；Android 未接 MDK 时播放行为不变（降级链可观测）。

### 4.3 M2 · Android 原生接 MDK（需真机）

1. 拉取 MDK Android `.aar`（含硬解 MediaCodec / FFmpeg）→ 放置 `android/app/libs/`；CI 脚本沿用既有 fetch 脚本模式
2. 新建 `MdkPlayer.kt`：与现有 Media3 / libVLC 两条线**同构**
   - 输入：`url` / `headers` / `isLive`
   - 输出面：复用 `TextureRegistry.SurfaceProducer`（MDK 写该 Surface）
   - 控制：open / play / pause / seekTo / setVolume / setSpeed / dispose
   - 事件：state / progress / videoSize / error
3. `PlayerPlugin.open` 增加 `backend == "mdk"` 分支
4. `teardown()` 补 MDK 资源释放

**验收**：MKV / HEVC / 10bit / HDR / 多音轨走 MDK 稳定播放；失败可回退 libVLC。

### 4.4 M3 · Windows / macOS 原生接 MDK（需真机）

- **Windows**：MDK `.dll`（D3D11）→ 在播放器插件中加 mdk 分支（或新增插件）
- **macOS**：MDK `.framework`（Metal）→ 在播放器插件中加 mdk 分支
- 渲染面同样接 Flutter 纹理，保持 UI 层一致

### 4.5 M4 · 收口

按 MDK 实测覆盖度决定 libVLC / libmpv 去留（决策口径：**VLC 作为复杂封装回退预留**，倾向保留）。

### 4.6 风险与口径

| 项 | 说明 |
|---|---|
| 许可 | MDK-SDK 为 **LGPLv2.1+**（含部分 FFmpeg 组件）→ 需动态链接 + 声明义务 |
| 包体 | 各端增加数 MB ~ 十几 MB |
| 构建 | CI 需拉 MDK 二进制（沿用既有 fetch / bundle 脚本模式） |
| 不覆盖 | **DRM**（Widevine / FairPlay）加密流 |
| 专用内核 | B站 IJKPlayer 与阿里 AliPlayer **不移植**，由 MDK 通用路径承担 |
| 验证边界 | 沙箱（Linux）**只能验证 M1**；M2 / M3 必须真机 |
