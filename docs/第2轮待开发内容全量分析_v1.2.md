## 2. 结论摘要

- **已对齐（勿重复开发，v1.2 扩充）**：设计基座 A、远程源/Spider B、播放器 C（含 Windows/macOS 插件、JSC 三端）、内容浏览 D、直播 E、网盘 F（12 家 + Node 托管 + B站 + extscreen）、扩展域 **G-02~G-09**（下载/推送/TG/单平台/TMDB/订阅/诊断/反馈）、福利 H（主体 + 5 类路由 + JS/Python Spider + 三重隔离）、我的/设置 I-01~I-04、JSC Q、备份还原 N、收藏/历史 M-03/M-04、源发现 O-05、后台音频 L-05、Windows 安装器 K-02、macOS 权限 K-03。
- **未对齐（需开发）**：**28 项**（业务域 24 + 资源/平台配置 4），详见 §4 总表。
- **iOS 平台专属（不移植，仅记录）**：MPVKit / MoltenVK / MDK / VT 渲染后端矩阵、AliyunPlayer SDK、DoubanImageProxyServer（豆瓣图片本地代理 + 夸克/lusushequ m3u8 转码代理）、AVPlayer/VTDecoderSession/ViewCapturePiP/AirPlay —— Flutter 四端（Android / Android TV / Windows / macOS）用各自等价方案。
- **口径待决策**：12+ 垂直站点服务族（MissAV / Kanliao / FullHD / XJSP…）是否逐站原生移植，还是统一「通用 Spider 引擎 + 远程源清单」覆盖。

## 7. 对齐口径说明

1. **「对齐」= 功能语义等价**，非文件 1:1。iOS Swift 文件 ↔ Flutter Dart 文件可多对一（如站点 Service 族 ↔ 通用 Spider 引擎）。
2. **「缺」= 连语义等价物都没有**，需新开发。
3. **「部分」= 有底座/契约键但缺关键片段**（如音乐有队列无音频引擎、日志有等级无分类、源治理有键无 UI）。
4. **「口径」= 需先定对齐边界**（站点服务族 / WebView 桥）。
5. **本轮对齐门槛提高**：v1.1 只判「有无文件」；v1.2 追加判「**是否可达**」——即使类/页面存在，若**未被任何入口引用**（如 MiniPlayer、`WelfareNativeRoute` 目标页），仍记为「部分/缺」。
