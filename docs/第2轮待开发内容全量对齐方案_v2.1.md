## 3. 详细开发步骤方案（每项：目标 → iOS参照 → 现状 → 步骤 → 验收）

### 3.1 P0 核心（先做，阻塞用户"能看到画面/封面/网盘"）

#### R-01 视频渲染输出面（四端）

- **目标**：四端能真正"看到画面"。
- **iOS 参照**：`MPVKitMetalLayer` / `MPVKitRenderView` / `MDKRenderView` / `LibmpvMoltenVKPlayerCore` / `VTDecoderSession`（Metal / MTKView 输出 CVPixelBuffer / MTLTexture）。
- **现状**：Windows libmpv `vo=null`；macOS AVPlayer 无渲染扩展；Android Media3 未绑 Surface；Dart 侧 `Texture`/`PlatformView` 命中 0。
- **步骤**（与 R-04 合做）：
  1. 完成 R-04 的 MDK 内核选定（见下）。
  2. 各端原生新建渲染宿主：Android 用 `PlatformView` 绑 `SurfaceView`（MDK `setVideoSurface`）；Windows/macOS 用 Flutter 原生插件把 MDK 渲染到 `FlutterTexture`（`TextureRegistrar`）或平台 View。
  3. Dart 侧新建 `VideoRenderView` widget（按平台选择 `PlatformViewLink` 或 `Texture`）。
  4. 打通 `PlayerController.open()` → 内核 `setSurface/textureId` 的回调链。
  5. 播放页挂载（见 R-02）。
- **验收**：四端各播 MKV/MP4/FLV/HLS 均显示画面；复杂封装见 R-03。

#### R-04 MDK 内核一统四端（决策落地）

- **目标**：单一 SDK 覆盖四端，替代三端异构。
- **iOS 参照**：`MDKPlayerEngine` / `MDKRenderView` / `MDKPipManager`。
- **现状**：三端异构（Media3/libmpv/AVPlayer），无 MDK。
- **步骤**：
  1. 引入 MDK SDK（Android `.aar`/`.so`、Windows `.dll`、macOS `.framework`），登记包体与许可（闭源）。
  2. 各端写 `MdkPlayerHost` 插件（init/setDataSource/setSurface/render/事件回调）。
  3. Dart `MdkPlayerBackend` 实现 `PlayerBackend` 接口，接入现有 `PlaybackRoute` + `PlayerController` 回退链（替换/新增 kernel）。
  4. 保留降级预案：MDK 在某端落地受阻 → 该端回退现多媒体后端（Media3/libmpv/AVPlayer）。
  5. conformance 补 MDK 后端回归。
- **验收**：四端统一走 MDK；失败可回退原有后端。

#### R-02 播放器 UI 挂载

- **目标**：把已建但零引用的控制条/子视图接入真实播放页。
- **iOS 参照**：`PlayerViewsV2` + `PlayerSubViews` + `PlayerViewsV2_Extensions`。
- **现状**：`PlayerControlsView`(370 行) + `widgets/player/` 子视图**全仓零引用**；`pages/` 无播放页。
- **步骤**：
  1. 新建 `PlayerPage`（横竖双态），内部挂 `R-01` 的画面容器 + `PlayerControlsView`。
  2. `DetailPage` 点击"立即播放" 从"Toast 占位"改为 `Navigator.push(PlayerPage)`。
  3. 接线控制条 ↔ `PlayerController`（进度/播放暂停/倍速/选集/下一集）。
  4. 挂弹幕 overlay 和字幕菜单。
- **验收**：点播放进入播放页，画面+控制条可用，进度条真实联动。

#### R-03 复杂封装回退落地

- **目标**：MKV/TS/RMVB/AVI/WMV 等复杂封装可回退播放。
- **现状**：Android `libVLC` 分支返回 `E_BACKEND_UNAVAILABLE`；macOS libmpv 未接线；仅 Windows libmpv 可用。
- **步骤**：
  1. Android 引入 libVLC `.aar` + `VlcPlayerHost`；`SimpleLibVlcBackend` 接 `setDataSource`+`attachView`。
  2. macOS 接线 libmpv（依赖 + 二进制 + `RenderContextPlayer`）。
  3. 校验 `PlaybackRoute`/`PlayerController` 的"复杂封装 → 回退后端"路由选择逻辑。
  4. 有转封装 fMP4 能力时优先转封装（见 R-01 联动 18081）。
- **验收**：四端各播一个 RMVB/AVI/WMV 成功或自动转封装 fMP4 成功。

#### ND-01 Node.js 运行时宿主

- **目标**：三端常驻 Node 进程，复用现有 Dart HTTP ABI。
- **iOS 参照**：`NodeMobile/NodeRunner.mm` + `NodeRuntimeManager` + `noderuntime/main.js` + `NodeSpiderEngine`。
- **现状**：Dart `node_bridge_engine`/`node_http_client`/`node_pan_client`/`node_credential_sync_service` 已做；三端原生无 Node 宿主。
- **步骤**：
  1. 选型：`nodejs-mobile`（移动）或预编译 Node 二进制随包分发（桌面）。三端统一版式后落地。
  2. 新建三端原生 `NodeHostPlugin`（启动/停止/健康检查/重启），监听 `127.0.0.1:58080`；LX 音乐 58083。
  3. 启动序列接入（并入 L-05-3）。
  4. `node_bridge_engine` 保持 HTTP ABI 不变；加"进程不可达 → 自动拉起/提示"重试。
  5. 内置 `noderuntime/`（main.js + lx-bridge.js + bundles），随包分发（控制包体，接入 §A-RES-02）。
- **验收**：四端经 `58080/spider/` 跑通 Node 站点 `homeContent/searchContent`；光鸭/蜗牛 Node 网盘解析播放可用。

#### IMG-01 封面统一代理 + 失败可观测

- **目标**：封面统一走本地代理（对齐 iOS `proxiedURL`），并让失败可见。
- **iOS 参照**：`DoubanImageProxyServer.proxiedURL` + `allowedHosts`(13) + `WelfareProxyStore`/`TMDBService.proxiedURL` 共用。
- **现状**：`PlatformAsyncImage` 分散 `Image.network(headers:)`，静默失败（占位盒掩盖 403）。
- **步骤**：
  1. 扩展 `go-proxy`（`package quarkproxy`，已有 `DiskCache`+路由）新增 `/image` 路由 + `allowedHosts` 白名单。
  2. `PlatformAsyncImage` 统一 URL 重写进 `/image` 代理，多域封面收敛到一个入口。
  3. `errorBuilder` 上报主机/状态码/原因到 `AppLog`（替代静默占位），并保留占位兜底。
  4. 与 F-01 网盘流代理共用 go-proxy 实例/缓存/端口规划。
