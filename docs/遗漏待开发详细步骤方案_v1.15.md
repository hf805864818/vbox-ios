## 2. 🔴 R-渲 · 播放渲染输出面（新增，P0）

> **一句话结论**：当前 Flutter 端**能解析地址、能驱动原生播放器、但没有画面**——「有声无画」。
> **证据（Dart 侧）**：全仓 `lib/` 检索 `Texture(` / `textureId` / `AndroidView` / `UiKitView` / `PlatformViewLink` = **0**；`PlayerControlsView` 仅自身定义、**全仓无引用**（无播放页承载）。

### 🔴 R-渲1 · 视频纹理输出面（四端全缺）— **P0**

**问题**：
- **Windows**：[player_plugin.h](file:///workspace/windows/runner/player_plugin.h#L18-L24) 明载「本插件为**控制面**实现……libmpv 以 `vo=null` 无窗口模式承载；视频纹理输出层（`mpv_render_context` + Flutter `TextureRegistrar`）属渲染层后续任务」；
- **Android / TV**：[PlayerPlugin.kt](file:///workspace/android/app/src/main/kotlin/com/vbox/player/PlayerPlugin.kt#L30-L32) 为 Media3 ExoPlayer 控制面，**未绑定 Surface**（无 `SurfaceView`/`TextureRegistry`）；
- **macOS**：[PlayerPlugin.swift](file:///workspace/macos/Runner/PlayerPlugin.swift#L88-L92) 为 AVPlayer 控制面，**无输出面**；
- **Dart**：无 `Texture`/`PlatformView` 消费点，`PlayerController.open()` 后无画面挂载路径。

**步骤**：
1. 各端原生新建**渲染宿主**：Android 用 `PlatformView` 绑 `SurfaceView`（`ExoPlayer.setVideoSurface`）；Windows 用 `mpv_render_context` + `TextureRegistrar` 输出到 `FlutterTexture`；macOS 用 `AVPlayerLayer` 平台视图（复杂封装再走 libmpv）；
2. 打通 Dart `PlayerController.open()` → 原生 `setSurface/textureId` 回调链；
3. new 一个 `VideoSurface` 组件（`Texture(textureId:)` / `PlatformViewLink`），按 `PlayerBackend` 选择承载。

**验收**：四端播放 HLS/MP4 可见画面；横竖屏尺寸自适应；切后台/回前台画面恢复。

### 🔴 R-渲2 · 播放页与控制层未挂载 — **P0**

**问题**：详情页 [detail_page.dart L169-L206](file:///workspace/lib/presentation/widgets/detail_page.dart#L169-L206) 的「立即播放」只调 `PlayerController.instance.open()/play()` 后 **Toast「开始播放」**；`PlayerControlsView`（[widgets/player/player_controls_view.dart](file:///workspace/lib/presentation/widgets/player/player_controls_view.dart)）全仓**零引用**，无全屏播放页、无控制条/进度条/选集面板挂载。

**步骤**：新增播放页（对齐 iOS `PlayerViewsV2` 的承载结构），把 R-渲1 的 `VideoSurface` + 既有控制层（`player_bottom_bar` / `player_top_bar` / `player_progress_bar` / 面板族）组装并接入路由；详情页「立即播放」改为进入播放页。

**验收**：点「立即播放」进入全屏播放页，控制条/弹幕/选集/画质/倍速/内核面板可用；返回详情页状态保持。

### R-渲3 · 复杂封装回退未落地（libVLC / libmpv 回退）— P2

**问题**：Android [PlayerPlugin.kt L147-L155](file:///workspace/android/app/src/main/kotlin/com/vbox/player/PlayerPlugin.kt#L147-L155) 对 `needed == LIBVLC` 直接返回 `E_BACKEND_UNAVAILABLE("……待 G-02-B/C 交付")`（`libvlc-all` 依赖已声明但未实现）；macOS [PlayerPlugin.swift L88-L92](file:///workspace/macos/Runner/PlayerPlugin.swift#L88-L92) 复杂封装同样返回 `E_BACKEND_UNAVAILABLE`（libmpv 回退未接线）。

**步骤**：Android 实现 libVLC 后端（`LibVLC` + `VLCVideoLayout` 或 `MediaPlayer` + Surface）；macOS 接入 libmpv 回退（依赖 D28 二进制分发）；Windows 已声明 libmpv 主后端，随 R-渲1 一并补齐。

**验收**：MKV/HEVC 无硬解等复杂源在对应端可播（不再 `E_BACKEND_UNAVAILABLE`）。

## 3. 运行时与分发链（新增）

### RT-运1 · Python 运行时（Android Chaquopy）未接入 — P2

**问题**：[android/app/build.gradle.kts L83-L90](file:///workspace/android/app/build.gradle.kts#L83-L90) 依赖区**无 Chaquopy**；`python_bridge_engine.dart` 走 `Process.start('python3')`，Android 无 `python3` 可执行 → **9 个 `y_*` Python 站 Android/TV 不可用**（主方案 §2.5 / §4.3 定稿为 Chaquopy）。

**步骤**：`build.gradle.kts` 引 Chaquopy（Gradle 依赖，零 NDK）；`PythonBridgeEngine` 增「可执行定位」抽象（优先 Chaquopy `Python.start()`）；无 Python 时站点解析为 `E_RUNTIME` 并在 UI 标注「该源需要 Python（此端不支持）」。

**验收**：9 个 `y_*` 站在 Android 可用；无 Python 源有明确降级文案。

### 🔴 K-更1 · 自更新器缺失 — P1

**问题**：全仓无 `Updater` 实现；设置页 [settings_page.dart L467-L472](file:///workspace/lib/presentation/pages/settings/settings_page.dart#L467-L472)「检查更新」= `Toast` 占位，副标题明写「**自更新将在 K 批次开放**」。对应主方案 §S.3（自动更新设计）/§S.4（Android 自更新）。

**步骤**：实现 `Updater`（拉取版本清单 → 对比 `AppInfo.version` → 下载 APK/安装包 → 校验 → 触发安装）；设置页「检查更新」接真实链路（含检查中/已最新/可更新/下载进度）。

**验收**：有新版本时提示并可下载；下载完成可跳转安装；无更新时文案正确。

### K-更2 · 版本分发清单与侧载引导缺失 — P2

**问题**：无版本分发清单（`version.json`/`latest`）消费方；主方案 §S.7（版本分发渠道）/§S.8（App 内安装引导）未落地。

**步骤**：定义并消费版本清单（版本号 / 下载地址 / 变更说明 / 哈希）；首启或「关于」提供侧载安装引导。

**验收**：清单可驱动 K-更1；引导页可指导用户完成侧载。

### K-更3 · Android 安装权限与自更新 FileProvider 缺失 — P1

**问题**：`AndroidManifest.xml` 现仅有**直播源导出分享**用 FileProvider（`${applicationId}.fileprovider`），**无 `REQUEST_INSTALL_PACKAGES`**，也无自更新 APK 的 FileProvider 路径配置 → 无法在应用内拉起安装。

**步骤**：声明 `REQUEST_INSTALL_PACKAGES`；新增自更新 APK 的 FileProvider 与 `file_paths`；安装前做「未知来源」授权引导。

**验收**：Android 应用内可成功拉起 APK 安装。

### M-安1 · macOS Release entitlements 缺 3 键 — P1

**问题**：[Release.entitlements](file:///workspace/macos/Runner/Release.entitlements) 仅 `com.apple.security.app-sandbox`；而 [DebugProfile.entitlements](file:///workspace/macos/Runner/DebugProfile.entitlements) 含 `network.server` / `cs.allow-jit`。构建配置 [project.pbxproj L644](file:///workspace/macos/Runner.xcodeproj/project.pbxproj#L644) 确认 **Release 用 Release.entitlements** → 发布版沙箱下**外网请求（`network.client`）/ Node 监听（`network.server` 58080/58083）/ QuickJS·libmpv JIT（`allow-jit`）**均会被拒。

**步骤**：Release entitlements 增 `com.apple.security.network.client` / `network.server` / `cs.allow-jit`（主方案 §2.5 口径）。

**验收**：Release 构建下外网解析、Node 桥、QuickJS 引擎可用。
