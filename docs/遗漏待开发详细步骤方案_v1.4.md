## 1. Welf-A · 福利服务层（6 项，WelfareRemote 深挖）

> v1.0~v1.3 已覆盖福利 Views 层，但 iOS `WelfareRemote/`（19 文件）服务层未系统深挖。本轮发现福利远程源架构 6 处断点。

### 🔴 Welf-A1 · 密码门控完整链路 — P1

**问题**：iOS 密码正确后**同时**置 `welfareUnlocked=true` + `welfareEnabled=true` + `refreshRemote()` 拉源 + 发 `.remoteWelfareShouldEnter` 通知（RemoteWelfarePasswordSheet.swift:221-253）；Flutter `unlock()` **只置 unlocked 不置 enabled**（welfare_controller.dart:78-85），个人中心弹窗「刷新」是**假的**（`Future.delayed(400ms)` + Toast，welfare_sheet.dart:75-82）——密码解锁与拉远程源完全脱钩。

**开发步骤**：
1. `WelfareController.unlock()` 内补 `enabled = true`；
2. welfare_sheet「刷新」接 `WelfarePlatformController.refresh()`（真请求）；
3. 新增解锁后一次拉源 + 状态通知（对齐 .remoteWelfareShouldEnter）。

**验收**：密码解锁即启用 Tab 并拉取远程源；首次进福利页数据已就绪。

### 🔴 Welf-A7 · 远程配置字段补全（29 → 15）— P1

**问题**：iOS `WelfarePlatformConfig` **29 字段**（含 `contentType`/`sslBypass`/`apiKind`/`detailMode`/`imageReferer`/`imageSSLBypass`/`headers`/`playerRefererMode`/`itemRule` 等，WelfarePlatformConfig.swift:96-220）；Flutter `welfare_platform_config.dart:51-69` 仅 15 字段。连锁后果：**`contentType` 丢失**→用 category 推断、**`imageReferer`/`imageSSLBypass` 恒 null/false**（fuli_base_service.dart:66-70）、**`sslBypass` 丢失**→JS 引擎无该参数。

**开发步骤**：实体 + tryParse 补全 14 个缺失字段 → `FuliBaseService` 消费 contentType/imageReferer/imageSSLBypass/sslBypass → JS/Python 服务读新字段。

**验收**：配置字段往返无损；按 contentType 正确分流；图片 referer/SSL 绕过生效。

### Welf-A2 · 启动自动 bootstrap — P2

**问题**：iOS 用 ObjC `+load` 启动早期自动 `bootstrap()` 预拉远程源（WelfareRemoteAutoLoader.m:31-53）；Flutter `app.dart:173` 仅 `new WelfarePlatformController()` **未调 bootstrap**，首次延迟到页面进入时。

**步骤**：`_bootstrap` 尾 `unawaited(_welfareRemoteController.bootstrap())`（非阻塞预拉）。**验收**：启动即拉远程源缓存。

### Welf-A4 · 首页拖拽排序 + 边缘滚动 + 震动 — P2

**问题**：iOS 长按拖拽排序（CADisplayLink 边缘自动滚动 + 三级震动 + 排序持久化，RemoteWelfareHomeView.swift:245-601）；Flutter `welfare_home_page.dart:15` 注释自认「未在本批实现」。

**步骤**：`ReorderableListView` + 拖拽边缘滚动 + `VboxHaptics`（UI-B1）+ 排序写 `fuli_remote_platform_order_v2`。**验收**：首页平台卡可长按拖拽排序并持久化。

### Welf-A5 · JS 蜘蛛 raw 函数兜底 — P2

**问题**：iOS `callRawFunction` 检测并执行 `homeVideoContent` 兜底 + `playerContent` raw 调用（WelfareJSSpiderService.swift:125-146、241-266）；Flutter 引擎层未暴露 `callRawFunction`，`homeVideoContent` 兜底**丢失**、`fetchPlayerURL` 无 typeof 检测（welfare_js_spider_service.dart:18-21、232-245）。

**步骤**：引擎桥暴露 `callRawFunction` + typeof 检测 + homeVideoContent 兜底。**验收**：仅有 homeVideoContent 的 JS 源可出首页内容。

### Welf-A6 · Python injectDict/localProxy/playerRefererMode — P2

**问题**：iOS `buildInjectDict` 注入 `_vbox_effective_hosts`/`_vbox_proxy_*`/`_vbox_ssl_bypass` + `callLocalProxy` + `playerRefererMode=="keep"` 头注入（WelfarePythonSpiderService.swift:61-75、199-219、411-413）；Flutter 无 localProxy、无 playerRefererMode 头注入、域名走 allHosts 近似（welfare_python_spider_service.dart:16-21）。

**步骤**：注入字典补全 + localProxy + playerRefererMode 头。**验收**：Python 蜘蛛域名/proxy/ssl 上下文正确注入。

> 归并不新增：m3u8 本地代理 = 已登记 Boot-H5；福利 Tab 门控内置版占位 = UI-C1（数据层经 Welf-A 补全）。

## 2. Res-B · 资源资产层（7 项）

**核心结论**：Flutter `assets/` 仅内置**品牌字体 + 1 张合成字母图**（pubspec.yaml:57-64），iOS 内置的全量资源 Flutter **零内置、全靠远程下发**。

### 🔴 Res-B1 · 内置订阅源 default_subscribe.json — P1

**问题**：iOS 内置 zhanyuan 站源 + B 站影视 + 磁力源（Resources/js/default_subscribe.json）；Flutter 无此文件，订阅源唯一来源是**用户手工添加 URL**（subscribe_config_store 默认空）——**新装用户无任何站源**，只能等远程订阅下发。

**步骤**：复制 default_subscribe.json 进 `assets/js/` + pubspec 声明 + 首次启动无订阅时加载内置种子。**验收**：新装 App 有默认站源可用。

### 🔴 Res-B3 · 蜘蛛 JS 库（cheerio/net/utils 等）— P1

**问题**：iOS 内置 `js/lib/`（cheerio.min.js/net.js/similarity.js/utils.js/zhanyuan_spider.js/模板.js）+ tetui_spider.js，由 `SpiderEngineFactory.injectLibraries` 加载；Flutter 只内嵌 `SpiderJsGlobals.prelude()`（console/print/atob/btoa 归一），**脚本全走远程 `loadScriptFromURL`**——站点诊断页已报「可能缺少依赖库如 cheerio/模板.js」（site_diagnostics_manager.dart:336）。

**步骤**：复制 JS 库进 `assets/js/lib/` + pubspec 声明 + 引擎加载时若远程失败则回退内置库。**验收**：依赖 cheerio/模板的站源可解析。

### 🔴 Res-B4 · Node bundle 完整内置 — P1

**问题**：iOS 内置 `noderuntime/`（main.js/lx-bridge.js/wexfnwconfig.json/kstore_index.js/db.json）；Flutter 无，Node 运行时 + lx 桥 + kstore 全部依赖远程 manifest 下发（remote_manifest.dart:72-73）。

**步骤**：并入 ND-02——确保远程 bundle 含全量 + 内置最小回退包（main.js 骨架）。**验收**：远程仓库不可用时 Node 核心可回退内置。

### 🔴 Res-B2 · 内置直播源 m3u — P2

**问题**：iOS 内置 default_live.m3u + live_default.m3u（Bundle 本地加载 + 本地兜底，LiveTVService.swift:742）；Flutter 无，直播默认源改为硬编码远程 URL（live_source_type.dart:105-116）。

**步骤**：内置 default_live.m3u + 远程源失败时本地兜底。**验收**：无网络时直播默认源仍可用。

### Res-B5 · python-stdlib 内置 — P2

**问题**：iOS 内置 python-stdlib/base/spider.py；Flutter 无，走系统 python3 子进程 + 远程 .py。

**步骤**：内置 spider.py 进 assets + 远程失败回退（并入 RT-01）。**验收**：Python 蜘蛛基础库可用。

### Res-B7 · 启动图资源补齐 — P2

**问题**：iOS 有 splash_letter_V/b/o/x + splash_swoosh 共 5 张；Flutter 仅 1 张合成 vbox_letter.png（UI-B4 资源未就位）。

**步骤**：补 swoosh + V/b/o/x 四字母图进 `assets/splash/` + UI-B4 动画资源对接。**验收**：启动动画资源匹配 iOS。

### Res-B6 · 字体 MaShanZheng — P3

**问题**：iOS 内置 MaShanZheng-Regular.ttf；Flutter 仅 VboxBrand-Bold.otf。

**步骤**：补 MaShanZheng 字体（若品牌标题/特定文案用到）。**验收**：需要该字体的场景一致。

## 3. Ckey-C · 契约键审计（3 项，98 键全量）

### 🔴 Ckey-C1 · 契约键零消费治理 — P1

**问题**：99 契约键中 **硬零 6 个**（多轮格式：`fallback_enabled`/`enable_dual_mode`/`quark_device_id`/`show_debug_overlay`/`dns_cache_clear`/`app_last_launch_version`）+ **软零 7 个**（`app_dev_log_enabled`/`app_dev_log_level`/`bundle_sources_enabled`/`welfare_platform_order`/`fuli_remote_platform_order_v2`/`custom_fallback_sites`/`user_parsers`）；其中 **`dns_cache_clear` 是误登记**（实为 IJK 播放器 FFmpeg 选项，非偏好键，v2.1 头部说移除 10 个误抓键但该键残留）。

**步骤**：纳入 S-07 守卫脚本（新增强：契约键消费扫描）→ 逐键接线或标记 NS 或删除误登键；`dns_cache_clear` 删除。**验收**：守卫脚本覆盖契约键；零消费键清零或登记 NS。

### 🔴 Ckey-C2 · 漏登记键补登 — P1

**问题**：iOS 有使用但 Flutter 契约**未登记**的键：
- `com.vbox.clouddrive.credentials_initialized_v1`（云盘凭据已初始化标记）
- `playback_progress_v2_<vodId>_<episodeIdx>`（播放进度）= **Pcore-D1 续播的地基**
- `skip_<vodId>_intro/outro_enabled/seconds`（片头尾）= UI-F2 数据契约
- `logvar_danmaku_<key>`（弹幕缓存）

**步骤**：补登契约 + 消费（进度键接 Pcore-D1，skip 键接 UI-F2）。**验收**：契约键完整覆盖 iOS 偏好集。

### Ckey-C3 · 键值格式/默认值分歧 — P2

**问题**：契约把多处 iOS 的 `Data`/`array` 键统一标 `string(JSON)`，跨端迁移不兼容：12 处类型不一致（searchHistory/welfare_platform_order/music_queue_items/push_play_items 等）+ 2 处时间（`Date` vs `long`）+ 9 处 `pg_ali_*`/`player_background_play` 默认值分歧（其中 `player_background_play` iOS 默认 `true` vs 契约 `false` 影响行为）。

**步骤**：契约标注实际存储类型（string/jsonlist/Data）+ 跨端迁移转换器 + 默认值统一（以 iOS 为准）。**验收**：备份/迁移跨端无损。

## 4. Pcore-D · 播放内核与会话（6 项）

### 🔴 Pcore-D1 · 播放进度保存 + 续播链路 — P0（最严重功能缺口）

**问题**：iOS 按集维度进度键 + 每 5 秒节流落盘 + `addOrUpdateHistory` + 退后台保存 + 打开即 seek（saved>10，PlayerViewsV2.swift:2109-2195、2770-2808）；Flutter **播放器层零进度落盘**——`playthrough.dart` 被误当「续播」实为**自动连播**，`PlayerSource.open` **无 resume 字段**，`HistoryUseCases.record` **全仓无播放器侧调用方**（历史表领域模型齐但内核链路完全没接）。**是 UI-F16 的深化：不止缺 seek，整条链路没接。**

**开发步骤**：
```dart
// 1. PlayerSource 加 resume 字段（player.dart）
class PlayerSource { final Duration? resumePosition; ... }

// 2. 播放器位置流节流 5s → HistoryUseCases.record（消费 playback_progress_v2_ 键）
// 3. 退后台保存进度（并入 Pcore-D2 生命周期）
// 4. 打开前查 resume（saved > 10s）→ PlayerController.open(resumePosition: ...) 后 seek
// 5. 进度 < 尾 15s 清除 + 收藏联动（对齐 iOS :2151-2163）
```
**验收**：播放中退出重进自动续播；历史页进度正确；播完清进度。

### 🔴 Pcore-D2 · 生命周期接线（PiP/后台/长按/连播）— P1

**问题**：`PipController`/`BackgroundPlayController`/`LongPressSpeedController`/`AutoPlayNextController` **全部只有定义，仓库内无 WidgetsBindingObserver/AppLifecycleState 调用点**——退后台/回前台行为实际不发生。是 S-07/UI-D3 的实锤深化。

**步骤**：PlayerPage 挂 `WidgetsBindingObserver` → `didChangeAppLifecycleState` 分派四控制器（后台：保存进度+按 backgroundPlay 开关决定暂停/继续；回前台：恢复）。**验收**：退后台行为符合开关；PiP 自动触发。

### Pcore-D3 · 系统 PiP 承载（帧桥/控制回传）— P2

**问题**：iOS 5 种 PiP 承载（AVSampleBufferDisplayLayer 帧桥 + AVPlayer 代理 + `setPlaying/skip/seek` 控制回传 + 失败降级链）；Flutter 只有 MethodChannel 桥（pip_bridge.dart:25-43 五方法），无帧桥、无控制回传、无降级。

**步骤**：macOS 用 AVKit PiP 桥 + Android 用系统 PiP（已有）；**优先**补 PiP 窗口内播放控制回传（play/pause/skip/seek MethodChannel 通道）；帧桥/硬解 PiP 视 macOS 实现补。**验收**：PiP 窗口可控制播放。

### 🔴 Pcore-D4 · 转封装内置解析器 — P1（R-03 深化）

**问题**：iOS `StreamRemuxer` 是**纯 Swift 手写** EBML/MKV/FLV 解析 + fMP4 生成 + 容器魔数检测（StreamRemuxer.swift:130-203）；Flutter `remux_proxy.dart` 依赖**外部 ffmpeg 可执行文件**（移动端无法保证存在），且仅扩展名判定（无魔数嗅探）、无后台保活。

**步骤**：纯 Dart 实现 MKV/FLV→fMP4 解析器（作为 ffmpeg 缺省时的降级）+ 魔数检测 + 后台保活。**验收**：无 ffmpeg 环境也可转封装播放。

### Pcore-D5 · 引擎事件面补齐 — P2

**问题**：iOS `PlayerEngineEvent` 有 `ready`/`buffering(Bool)` 双向/`log` 诊断流 + `PlayerEngineState` 快照含宽高（PlayerEngineEvent.swift:4-11）；Flutter 用**字符串 map 分派**，无 ready 事件、无 buffering 双向、无 log 诊断流、无视频宽高快照。

**步骤**：类型化事件枚举 + `ready`/`buffering(bool)` + 诊断日志流（前 80 条转发）+ 宽度/高度快照。**验收**：加载态「解析中/缓冲中」区分；诊断可上抛。

### Pcore-D6 · 锁屏 NowPlaying / 遥控 / 防锁屏 — P1

**问题**：iOS 音乐侧有 NowPlaying 元数据 + MPRemoteCommandCenter（play/pause/next/prev/seek）+ 防锁屏 isIdleTimerDisabled；Flutter 视频/音乐侧均无，Android `MediaPlaybackService` 只是空壳（无 controller 回调）。

**步骤**：并入 Music-K7（音乐）+ UI-F15（audio_service）——`audio_service` AudioHandler 实现 play/pause/seek 远程命令 + 锁屏 NowPlaying 元数据 + 播放中防锁屏（UI-D2 wakelock 已列）。**验收**：锁屏可显示曲目并控制播放。
