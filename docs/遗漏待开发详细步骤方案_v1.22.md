# vbox 遗漏待开发详细步骤方案 v1.22

> **版本**：v1.22 —— 在 [v1.21](computer:///workspace/docs/遗漏待开发详细步骤方案_v1.21.md)（10 项未开发 + 验收 3）基础上，交付 **ND-01 · Node 常驻系统**（跨平台宿主接缝 + 运行时管理器 + 启动编排 + Android nodejs-mobile 通道）+ **ND-01-native · 原生引擎接入**（CI 拉取官方预编译 + JNI 桥，**机制对齐 iOS**）+ **ND-02 · bundle 交付**（随包内置 folder reference + 远端 manifest 增量刷新），并**逐档对齐 iOS `NodeRuntimeManager.swift` / `VBoxApp.swift` / `RemoteSourceConfigManager.swift` / `build-ipa.yml` / `NodeRunner.mm`**；此举解除 NC-清5 挂起的 **P0 依赖**（Node 就绪通知源）。
> **核对日期**：2026-10-06
> **数据源**：iOS `vbox/Services/NodeRuntimeManager.swift`（L30-L751，738 行逐档核对）+ `scripts/configure_noderuntime_link.rb` + v1.21 + 仓库代码（HEAD `4aeac3f` + 本批工作区改动）
> **核心原则（强制）**：UI 层一律以 iOS 端为准（35 张真机截图 + 54 个 Swift 源码）。

> **本轮要点**：
> 1. **Node 常驻系统落地（ND-01）**：新增平台层 [node_ports.dart](file:///workspace/lib/platform/node/node_ports.dart) / [node_host.dart](file:///workspace/lib/platform/node/node_host.dart) / [node_runtime_manager.dart](file:///workspace/lib/platform/node/node_runtime_manager.dart)，实现「部署运行时文件 → bundle 完整性 → 拉起宿主 → 后台刷 bundle → HTTP 探活就绪 → 30s 心跳 → 15s lx 探活 → 崩溃重启」全编排，与 iOS `start()` 六步 1:1。
> 2. **跨平台宿主接缝**：`NodeHost` 抽象 + `ProcessNodeHost`（macOS / Windows / 测试，`node <main.js>` 子进程）+ `ChannelNodeHost`（Android，nodejs-mobile **进程内引擎**）+ `UnavailableNodeHost`（未接入降级）；两宿主对上层语义等价，**就绪判定与心跳一律走 HTTP 探活**（对齐 iOS）。
> 3. **Android 原生接入（ND-01-native，机制对齐 iOS）**：新增 [NodePlugin.kt](file:///workspace/android/app/src/main/kotlin/com/vbox/player/NodePlugin.kt)（通道 `com.vbox.node/host`，端口矩阵经 `Os.setenv` 注入）+ [NodeBridge.kt](file:///workspace/android/app/src/main/kotlin/com/vbox/player/NodeBridge.kt)（JNI 桥，等价 iOS `NodeRunner`）+ [node_bridge.cpp](file:///workspace/android/app/src/main/jni/node_bridge.cpp)（`node::Start(argc,argv)`）+ [CMakeLists](file:///workspace/android/app/src/main/jni/CMakeLists.txt) + [fetch 脚本](file:///workspace/scripts/fetch-nodejs-mobile-android.sh)；**与 iOS `build-ipa.yml` 同源同版本**（nodejs-mobile v18.20.4）拉取预编译库。缺包时回 `E_NODE_UNAVAILABLE`，**降级不 crash**。
> 4. **iOS 对齐补强（本轮新增）**：① **就绪预算** 12s → **45s**（对齐 iOS `waitForStartupAck(45s)`），慢设备不再误判 `node-failed`；② **心跳容差** 单次探活 → **12 次 × 500ms**（对齐 iOS `runHealthCheck → probeHealth(retries: 12)`），网络抖动不再被放大为「判崩溃 → 自动重启」而打断正在播放的网盘链路。
> 5. **启动编排接线**：Node 以 `unawaited` 后台拉起（**不阻塞首屏**，对齐 iOS 在后台 `Task` 起），就绪经 `statusStream` 触发 NC-清5 凭据自动推送（闭环 v1.21 §1 NC-清5 登记的 P0 依赖）。
> 6. **bundle 交付对齐 iOS（ND-02）**：`bundles/kstore_index.js`（6.5MB）**随包内置**（等价 iOS `Resources/noderuntime` folder reference，`configure_noderuntime_link.rb`）；远端 manifest 的 `nodeRuntimeBundle` / `nodeRuntimeBundleVer` 同步进契约键 `remote_node_bundle_url` / `remote_node_bundle_ver`，启动时读取后做**可选增量刷新**（后台、下次启动生效，对齐 iOS `cachedNodeBundleRefreshURL()` → `start(...)`）；`verifyBundleIntegrity` 收紧为对齐 iOS —— 内置资源缺失即抛错（不再静默放行）。
> 7. **未开发项 10 → 10**（不变，全部在福利域）；**P0 依赖项 ND-01 清零**；新增 **19** 个 Node 单测用例 + **2** 个数据层用例（镜像键 / 缓存地址读取）。
> 8. **ND-01-native 已接入（机制对齐 iOS）**：Android 由 CI/脚本拉取 **nodejs-mobile v18.20.4 官方预编译**（与 iOS `build-ipa.yml` 同 release、同 curl 重试口径）→ `libnode.so`（**三 ABI**：armeabi-v7a / arm64-v8a / x86_64，官方 v18.20.4 已停供 x86）+ `node.h` 头文件 → JNI 桥 `node_bridge.cpp` 调 `node::Start`（等价 iOS `NodeRunner.mm` 调 `node_start`）。**桌面端**沿用 iOS「独立进程」语义的 `ProcessNodeHost`（系统 `node`，D29 决策）。
> 9. **残余仅为已登记的有意差异**：NS-16（`.startup.ack` / `.relisten` 文件握手不移植，就绪由 HTTP 探活等价）与 `unsetenv("TVS_PARENT_PID")` 未移植。

## 1. ND-01 交付记录（Node 常驻系统）

### ✅ ND-01 · Node 常驻系统 — 已交付

**问题**（v1.15 登记 · v1.21 挂起为 P0 依赖）：iOS 在 App 启动时于后台拉起 nodejs-mobile 常驻引擎，承载网盘取流 / 站点爬虫 / lx-music 桥接；Flutter 侧宿主缺失，导致 **Node 站点不可用、网盘取流（夸克/UC/阿里）与播放链路缺一环**。用户明确「Node 常驻系统直接影响播放问题」，要求分析 iOS 并对齐开发。

#### ⑨ 原生引擎接入（ND-01-native，机制逐档对齐 iOS）

iOS 的做法：`build-ipa.yml` 从 **nodejs-mobile 官方 release** 下载 `NodeMobile.xcframework` →
`ruby scripts/configure_noderuntime_link.rb` 注入 Xcode 工程 → `NodeRunner.mm` 调 `node_start`。
Flutter Android 端**照搬同一机制**（同 release、同版本、同 curl 重试口径）：

| iOS | Flutter Android | 说明 |
|---|---|---|

> **桌面端**：iOS 为「内嵌单实例」，桌面端沿用 iOS 的**独立进程**语义（`ProcessNodeHost` 起 `node` 子进程，`includeParentEnvironment: true`）——与 D29（桌面系统探测 `node`）一致；不随包内嵌 Node 二进制。

#### 已登记差异（逐条）

1. **NS-16（文件握手不移植）**：iOS `.startup.ack` / `.relisten` / `.relisten.ack` 三处文件握手协议不移植 —— iOS 用它跨「App 挂起/恢复」与「Node 单实例重启」做进程编排；Flutter 宿主为独立子进程 / 进程内通道，进程生命周期由 Dart 侧把控，就绪语义改由 **HTTP 探活等价判定**。
2. **崩溃可自动重启（桌面可，Android 受限——与 iOS 同限）**：nodejs-mobile 运行时**单实例且不可进程内重启**（iOS / Android 均如此，`NodeBridge` 以 `isStarted` 守卫重复启动）。故 [_attemptRestart](file:///workspace/lib/platform/node/node_runtime_manager.dart#L619)（上限 3 次）在**桌面**（`ProcessNodeHost` 独立子进程）可真正重启；**Android** 与 iOS 一致——引擎退出后无法原地重启，最终降级 `node-failed`（提示重启 App），语义与 iOS `handleNodeCrash` 对齐。
3. **`unsetenv("TVS_PARENT_PID")` 未移植**：iOS 为规避父进程看门狗退出而清除该变量；桌面 `ProcessNodeHost` 用 `includeParentEnvironment: true` 继承父环境，Android 进程内引擎无该变量，故不需清除。
4. **代码文件覆盖策略**：iOS 按 `isResourceNewer`（mtime 比对）决定是否覆盖；Flutter `prepareRuntimeFiles` 对代码文件直接覆盖（`overwrite: true`），语义等价且更简单（App 升级携带修复）。
5. **~~内置 bundle 缺失时放行~~（ND-02 已收紧对齐）**：ND-02 交付前 Flutter 曾因 6.4MB 不随包，资源缺失时记警告放行；现 bundle 已随包内置，`verifyBundleIntegrity` 已收紧为**资源缺失即抛错**，与 iOS `bundleResourceMissing` 一致。

**验收**：新增 [node_runtime_manager_test.dart](file:///workspace/test/platform/node/node_runtime_manager_test.dart) **19 例**，覆盖 8 类语义：启动全链路 / 环境变量矩阵 / 生产缺省对齐 iOS / 代码覆盖与数据保护 / 内置资源缺失降级 / 拉起失败 / 就绪探活失败 / 心跳连续失败判崩溃并重启 / 崩溃自愈 / 内存告警与未就绪忽略 / **启动即用内置 bundle（落盘 + `source=bundled` + `BUNDLE_PATH`）** / bundle 完整性（一致·回退·**内置缺失抛错**）/ 远端刷新（版本一致·下载原子写·<1MB 丢弃）/ lx 独立探活。另加 **2 个数据层用例**：`saveManifest` 镜像 Node bundle 键（[remote_source_repository_test.dart](file:///workspace/test/data/repositories/remote_source_repository_test.dart#L110)）、`cachedNodeBundle*` 读取（[remote_source_config_manager_test.dart](file:///workspace/test/data/datasources/remote/remote_source_config_manager_test.dart#L549)）。

### ⚙ iOS 对齐补强（本轮，直接影响播放稳定性）

| 项 | 改前 | 改后 | 对齐依据 |
|---|---|---|---|
| 就绪预算 | `readyProbeRetries = 24`（≈12s） | **`= 90`（45s）** | iOS `waitForStartupAck(timeout: 45)`；Flutter 不移植 ack，故把整段预算给 HTTP 探活，避免慢设备「引擎未监听 → 误判 `node-failed`」 |
| 心跳容差 | `runHealthCheck → probeHealth()`（1 次） | **`probeHealth(retries: 12, retryDelay: 500ms)`** | iOS `runHealthCheck → probeHealth()` 默认 12 次；单次抖动不直接计失败，避免「误判崩溃 → 自动重启」打断网盘取流 / 播放 |
