# vbox 遗漏待开发详细步骤方案 v1.20

> **版本**：v1.20 —— 在 [v1.19](computer:///workspace/docs/遗漏待开发详细步骤方案_v1.19.md)（17 项未开发 + 验收 3）基础上，记录 **Wave G（播放内核 + 运行时）**：R-渲3 · 复杂封装回退（Android libVLC / macOS libmpv）→ RT-运1 · Python 运行时（Android Chaquopy）。
> **核对日期**：2026-10-06
> **数据源**：仓库代码（HEAD `46c3308` + 本批工作区改动）+ Chaquopy 官方文档（17.0 版本矩阵 / Gradle 接入）+ v1.19
> **核心原则（强制）**：UI 层一律以 iOS 端为准（35 张真机截图 + 54 个 Swift 源码）。

> **本轮要点**：
> 1. **播放内核补齐（R-渲3）**：Android 新增 **libVLC 回退后端**（复杂封装 MKV / FLV / TS / RMVB / AVI / WMV / M2TS、HEVC 无硬解），输出面沿用 R-渲1 的 `TextureRegistry.SurfaceProducer`（libVLC 直接写 Flutter 纹理，**Dart 侧仍是 `Texture(textureId:)`，UI 层与 iOS 一致**，无 PlatformView）；macOS 新增 **libmpv 回退后端**（`dlopen` 动态加载 + SW 渲染上下文 → Flutter Texture，与 Windows 同口径）；CI 补 macOS debug 的 libmpv dylib 打包步骤。
> 2. **运行时补齐（RT-运1）**：Android 经 **Chaquopy 17.0** 随 APK 打包 CPython，新增原生通道 `com.vbox.python/python`（`PythonPlugin.kt`）与 Python 侧引导模块（`vbox_python_bridge.py`），把 stdio ABI **原样复刻**（替换 `sys.stdin` / `sys.stdout` / `sys.stderr`），使既有蜘蛛脚本**零改动复用**；Dart 侧抽出 `PythonRuntime` 抽象并按平台分派，Android 走进程内解释器、其余平台仍走 `python3` 子进程。
> 3. **未开发项 17 → 15**（P0 **0** · P1 **2** · P2 **7** · P3 **6**）；验收项仍 3。
> 4. **关键兼容性核对（本轮结论）**：Chaquopy 17.0 支持 **AGP 7.3–9.2**，本工程 AGP **9.1.0** 命中区间（16.0 仅到 AGP 8.8，不可用）；minSdk 24 恰为下限；Python 选 **3.11** 以保留 32 位 `armeabi-v7a`。
> 5. **已登记取舍**：Chaquopy 每 ABI 为 APK 增加数 MB（随 `--split-per-abi` 分摊到单 ABI 包体）；`pyc.src = false` 使构建不依赖构建机 Python（CI 免额外前置，代价为首次运行设备端编译脚本）。

## 1. Wave G 交付记录（播放内核 + 运行时）

### ✅ R-渲3 · 复杂封装回退（Android libVLC / macOS libmpv） — 已交付

**问题**（v1.19 登记 · P2）：`backend=libVLC` / 复杂封装媒体在两端均不可播 —— Android 直接返回 `E_BACKEND_UNAVAILABLE`，macOS 无 libmpv 后端。

**落地口径**（对齐 A21.5 回退策略 + D6 后端链，**UI 层与 iOS 一致**）：

- **Android · libVLC 回退**（[PlayerPlugin.kt](file:///workspace/android/app/src/main/kotlin/com/vbox/player/PlayerPlugin.kt)）：
  - `open` 按后端分派：`media3`（且媒体无需回退）走 ExoPlayer；`media3` 但被 `CodecCapability.selectBackend` 判为 libVLC → 仍回报 `E_BACKEND_UNAVAILABLE`，由 Dart `PlayerController` 按**降级链**改投 libVLC（降级可观测，C-06）；`libVLC` → `openVlc`；
  - **输出面沿用 R-渲1**：`TextureRegistry.createSurfaceProducer()` → `IVLCVout.setVideoSurface(surface, null)` + `attachViews(layoutListener)`，画面直接进 Flutter 纹理；Dart 侧仍 `Texture(textureId:)`，**不引入 PlatformView**；
  - 事件映射：`Opening / Buffering / Playing / Paused / Stopped / EndReached / EncounteredError / TimeChanged / LengthChanged / Vout` → 既有 `state / progress / videoSize / error` 事件；`Buffering` 高频率去重（< 100% 才报 buffering）；
  - 控制面接线：`play / pause / seekTo(setTime) / setVolume(0~100 域) / setSpeed(setRate)`；请求头经 `applyHeaders` 映射为 libVLC 选项（`:http-referrer` / `:http-user-agent`）；
  - **切后台回前台画面恢复**：`onSurfaceAvailable → rebindVlcSurface()`（detachViews → setVideoSurface → attachViews），`onSurfaceCleanup → detachViews`。

- **macOS · libmpv 回退**（[PlayerPlugin.swift](file:///workspace/macos/Runner/PlayerPlugin.swift)）：
  - `dlopen("Contents/Frameworks/libmpv.dylib")` 动态加载（D28 随包分发；缺失时返回 `E_BACKEND_UNAVAILABLE`，**不 crash**），`dlsym` 绑定 `mpv_*` 与 `mpv_render_context_*` 符号；
  - `openWithMpv`：`vo=libmpv`（无 render API 时退 `vo=null`）→ `loadfile replace` → `observe_property`（`time-pos` / `duration` / `pause` / `paused-for-cache` / `demuxer-cache-time`）；
  - 渲染输出面：`mpv_render_context` 以 **SW 渲染** 产出 BGRA 像素缓冲 → 经 `FlutterTexture` 上屏（与 Windows libmpv 实现同口径）；
  - 事件循环线程 `mpvEventLoop` → `state / progress / videoSize / error` 事件；点播起播后置 `pause=1` 待 Dart `play()`，直播直接起播。

- **CI**（[flutter-check.yml](file:///workspace/.github/workflows/flutter-check.yml)）：macOS debug 构建新增 `scripts/bundle-libmpv-macos.sh --config Debug`，缺失资产即失败（暴露 D28 分发缺口）；与 `build-release-assets.yml` macOS job 对齐。

**验收**：后端分派（media3 / libVLC / 未知后端）、请求头映射、降级链可观测 —— Dart 侧由既有 `player_controller` 用例覆盖；原生 libVLC / libmpv 实播需真机（马赛克名单见 §3）。

### ✅ RT-运1 · Python 运行时（Android Chaquopy） — 已交付

**问题**（v1.19 登记 · P2）：Android 无 `python3` 可执行文件，Dart 桥原以 `Process.start('python3', …)` 起子进程 → **9 个 `y_*` Python 站点在 Android / TV 全不可用**。

**落地口径**：

- **构建接入**（[settings.gradle.kts](file:///workspace/android/settings.gradle.kts#L24-L27) · [build.gradle.kts](file:///workspace/android/app/build.gradle.kts)）：
  - `com.chaquo.python` 版本 **17.0.0**（支持 AGP 7.3–9.2；本工程 AGP 9.1.0 命中区间，16.0 仅到 8.8 不可用）；
  - `defaultConfig.ndk.abiFilters` 收敛为 **armeabi-v7a / arm64-v8a / x86_64**（Chaquopy 解释器为原生组件，须显式声明；与 `flutter build apk --split-per-abi` 产物一一对应）；
  - `chaquopy.defaultConfig`：`version = "3.11"`（保留 32 位 ABI）、无 pip 依赖（`y_*` 脚本仅用标准库）、`pyc.src = false`（构建不依赖构建机 Python）。
- **原生通道**（[PythonPlugin.kt](file:///workspace/android/app/src/main/kotlin/com/vbox/player/PythonPlugin.kt) · MethodChannel `com.vbox.python/python`）：
  - `launch(script, timeoutMs)` → 启动并等待首行 `READY`；`request(line, timeoutMs)` → 一行响应；`shutdown` → 关闭（幂等）；
  - 线程模型：脚本运行在常驻线程 `vbox-python-spider`，阻塞于 `StdioBridge.readLine()`；通道回调在平台主线程，故重活派发单线程执行器（**保序**）、结果回投主线程（**避免 ANR**）。
- **Python 侧引导**（[vbox_python_bridge.py](file:///workspace/android/app/src/main/python/vbox_python_bridge.py)）：用 Kotlin 传入的 io 对象替换 `sys.stdin` / `sys.stdout` / `sys.stderr`（Chaquopy 下 `sys.stdin` 恒为 EOF），使**同一份 stdio ABI 脚本零改动复用**（与子进程版共用源码）。
- **Dart 侧抽象**（[python_runtime.dart](file:///workspace/lib/platform/spider/python_runtime.dart) · [python_bridge_engine.dart](file:///workspace/lib/platform/spider/python_bridge_engine.dart)）：
  - `PythonRuntime` 抽象 + `forCurrentPlatform` 分派：`Platform.isAndroid` → `ChannelPythonRuntime`（Chaquopy）；其余 → `StdioPythonRuntime`（`python3` 子进程，行为不变）；
  - 引擎仅编排 ABI（编码 / 解码 / 状态），宿主对上层无感知；
  - **降级可观测**：通道未注册（`MissingPluginException`）→ `E_UNIMPLEMENTED`（提示「Python 运行时不可用」，不 crash）；原生 `E_TIMEOUT` / `E_PY_RUNTIME` 分别映射超时 / 运行时错误。

**验收**：新增 [python_channel_runtime_test.dart](file:///workspace/test/platform/spider/python_channel_runtime_test.dart) 6 例（通道名一致、launch/request 参数透传、`MissingPluginException` → `E_UNIMPLEMENTED`、`E_TIMEOUT` → 超时、`E_PY_RUNTIME` → 运行时错误、引擎注入通道运行时后的 ABI 端到端解码），经 `TestDefaultBinaryMessenger` mock，无真实插件依赖；既有 `python_bridge_engine_test.dart`（真实 `python3` 子进程 8 例）行为不变。
